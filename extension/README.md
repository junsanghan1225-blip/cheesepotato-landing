# 치즈감자 크롬 익스텐션

everykoreans.com 의 사전·문법·표현을 **읽던 쪽 위로** 가져간다. 한국어로
된 기사·댓글·자막을 읽다가 막혔을 때 사이트로 건너가지 않고 그 자리에서
뜻을 본다.

하는 일은 셋이다.

1. **선택 사전** — 아무 쪽에서나 한국어를 끌면 말풍선으로 뜻·품사·예문이
   뜬다. 그 문장에 든 문법도 함께 짚어 준다.
2. **문법 밑줄** — `Alt+G` 로 그 쪽의 아는 문법 197개에 밑줄을 긋는다.
   밑줄을 누르면 무슨 문법인지 나온다.
3. **새 탭 카드 · 단어장** — 새 탭마다 표현이나 낱말 한 장. 담아 둔 낱말은
   간격 반복(1 → 3 → 7 → 16 → 35 → 90일)으로 돌아온다.

---

## 굽고 올리기

`extension/data/` 는 **저장소에 없다.** 먼저 구워야 한다.

```bash
node tools/build-extension.mjs      # 사이트 자료 → extension/data/ (2.6MB)
```

그다음 크롬에서 `chrome://extensions` → 「개발자 모드」 → 「압축해제된 확장
프로그램을 로드합니다」 → 이 `extension/` 디렉터리.

웹 스토어에 올릴 꾸러미는 이 디렉터리를 통째로 zip 하면 된다.

```bash
node tools/build-extension.mjs && node tools/check-extension.mjs \
  && (cd extension && zip -qr ../cheesepotato.zip . -x '*.DS_Store' 'README.md')
```

### 사전을 고쳤으면 다시 구울 것

```bash
node tools/build-extension.mjs --check     # 낡았으면 종료 코드 1
node tools/check-extension.mjs             # 위의 것 + manifest·쪽이 없는 파일을 안 부르는지
```

`glossary.js` 나 `sentences*.js` 를 고치고 이걸 안 돌리면 **사이트와
익스텐션이 다른 뜻을 내준다.** 그것도 틀린 줄 모르는 채로 — 익스텐션은
멀쩡히 돌아가고 예전 뜻을 정확하게 보여 준다. `stamp.mjs` 를 빼먹었을 때와
같은 종류의 사고다.

  store.js         설정·단어장·간격 반복

  theme.css        사이트와 같은 색 토큰

## 왜 이렇게 했나

### 사전을 통째로 싣는다 — 서버에 안 묻는다

번역기를 부르려면 열쇠가 있어야 하는데 그걸 익스텐션에 넣으면 그대로
공개된다(사이트가 사전을 들고 다니기로 한 것과 같은 까닭이다). 그래서
사전 4,209 표제어와 문법 197개를 익스텐션 안에 넣었다. 2.6MB 다.

덕분에 **인터넷이 끊겨도 그대로 되고, 무엇을 찾았는지가 아무 데도 안
간다.** `manifest.json` 에 `host_permissions` 가 없는 것이 그 증거다.
딱 하나, 발음을 「사이트 녹음」으로 바꾸면 그때만 everykoreans.com 에서
mp3 를 받아 온다 — 그 요청에도 referrer 는 안 붙인다.

### 찾기는 서비스 워커가 한다

`content/content.js` 는 사람이 여는 **모든 쪽**에 들어간다. 거기서 사전
360KB 를 읽으면 한국어가 한 글자도 없는 쪽에서도 그 값을 물고, 탭이
스무 개면 스무 번이다. 그래서 말풍선은 끌어 놓은 글만 보내고 찾기는
서비스 워커가 한다. 서비스 워커는 브라우저에 하나뿐이다.

팝업과 새 탭은 서비스 워커에 안 묻고 `look.js` 를 직접 부른다 — 저희가
이미 익스텐션 쪽(page)이라 한 번 더 건너갈 까닭이 없다.

### 자료는 `.json`, 코드는 `.js`

처음에는 자료도 모듈로 굽고 `await import()` 로 필요할 때 받았다.
화면에서는 잘 됐고 **서비스 워커에서만 안 됐다** — 서비스 워커 안에서는
동적 `import()` 가 금지되어 있다([w3c/ServiceWorker#1356]). 팝업에서는
뜻이 멀쩡히 나오는데 말풍선에서만 「못 찾았습니다」가 떴다. 고장 난 자리와
원인이 멀어서 알아보기 어려운 종류였다.

`fetch` 는 서비스 워커에서도 화면에서도 똑같이 되고 `eval` 도 안 쓴다
(MV3 가 막아 둔 것이다). 그래서 필요할 때 받는 자료는 전부 JSON 이다.

[w3c/ServiceWorker#1356]: https://github.com/w3c/ServiceWorker/issues/1356

### 남의 쪽을 안 건드린다

말풍선은 Shadow DOM 안에 있다. 읽던 쪽의 CSS 가 말풍선을 망가뜨리지도,
우리 CSS 가 읽던 쪽으로 새지도 않는다.

문법 밑줄은 **CSS Custom Highlight** 로 긋는다. `<span>` 을 끼워 넣으면
남의 쪽 배치가 깨지고, 리액트로 그린 쪽에서는 다음 그리기에 통째로
날아간다. Highlight 는 DOM 을 한 글자도 안 고치고 Range 만으로 칠한다.

대신 **글월(text node)을 넘나드는 문법은 못 잡는다.** `<b>오는</b> 바람에`
처럼 태그로 갈린 자리가 그렇다. 한 글월 안에 있는 것만 긋는다.

### 문법이 집은 자리는 사전을 안 붙인다

「비가 오는 바람에」의 「바람에」를 사전에서 찾으면 `wind` 가 나온다.
바람이 분 적이 없는 문장인데도 그렇다 — 여기 「바람」은 문법
「-는 바람에」의 한 조각이지 낱말이 아니다.

사이트의 규칙이 여기서도 그대로다: **틀린 뜻을 내주느니 빈 칸을 내준다.**
빈 칸도 아니다 — 그 자리는 바로 윗줄의 문법이 이미 설명하고 있다.

### 글꼴을 안 싣는다

사이트 본문은 Pretendard 를 쓰지만 `vendor/pretendard` 가 3.1MB 다.
이걸 실으면 익스텐션이 두 배가 넘게 무거워진다. 정적 쪽이 이미 같은
까닭으로 기기 글꼴을 쓰기로 했고(뿌리 README 「검색에 걸리게 하는 것」),
여기도 그 판단을 따른다.

### 카드는 하루에 하나로 묶는다

탭을 열 때마다 다른 카드가 뜨면 하나도 안 읽게 된다. 다음 카드가 한 번의
클릭이면 읽는 것보다 넘기는 것이 쉽기 때문이다. 날짜로 고정해 두면 그날
몇 번을 열든 같은 카드라, 세 번째 열 때쯤에는 읽는다.

## 알아 둘 것

- **새 탭을 되돌리는 길이 없다.** 크롬은 「원래 새 탭으로 돌려 달라」는
  길을 익스텐션에 안 열어 준다. 설정에서 「안 보기」로 두면 빈 쪽이
  나오고, 진짜로 되돌리려면 `chrome://extensions` 에서 익스텐션을 꺼야
  한다. 설정 쪽과 그 빈 쪽에 그렇게 적어 두었다.
- **최소 크롬 116.** CSS Custom Highlight 와 MV3 때문이다.
- **단어장은 이 기기 안에만 있다.** 기기를 옮기려면 설정에서 TSV 로
  복사해 가면 된다(안키·스프레드시트에 그대로 붙는다).
- **문법은 197개다.** 사이트의 표현은 290개지만, 93개는 이름이 꼴이
  아니라 설명이거나(「'ㅂ' 불규칙」) 너무 짧아서(「-고」) 글에서 찾을
  자국이 못 된다. 새 탭 카드에는 290개가 다 나온다.
