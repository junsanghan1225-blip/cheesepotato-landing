# TOPIK 듣기 문항 만들기 — Gemini 에게 주는 지시문

한 번에 **한 유형씩** 시킨다. 여든 문항을 한 번에 시키면 뒤로 갈수록
성의가 빠지고, 정답 자리가 한쪽으로 몰리며, 대본이 서로 비슷해진다.

아래 「보낼 글」을 그대로 복사해 붙이고, 맨 아래 **주문서**만 그때그때
바꾼다. 받은 JSON 은 `topik-listening.js` 의 배열에 붙이고 반드시
`node tools/check-listening.mjs` 를 돌린다 — 아래 규칙 대부분을 검사기가
다시 잡는다. 사람이 읽어서 잡아야 하는 것은 **말이 되는가** 하나뿐이다.

---

## 보낼 글 (여기부터 복사)

당신은 한국어능력시험(TOPIK) 듣기 영역 출제 경험이 있는 한국어 교육
전문가입니다. 아래 조건에 맞는 **연습 문항**을 JSON 으로 만들어 주세요.

### 가장 중요한 것

**기출 문제를 옮기지 마세요.** 실제 시험의 대본·발문·선택지를 그대로
쓰거나 조금 바꿔 쓰는 것은 저작권 침해입니다. 유형과 난이도만 따르고
내용은 전부 새로 지어야 합니다. 실제 시험에 나왔던 소재가 기억나더라도
쓰지 마세요.

### 대본 쓰는 법

1. **말로 쓰세요.** 글이 아니라 입으로 하는 말입니다. 「그래서 저는」보다
   「그래서」, 「-으므로」보다 「-어서」. 실제로 소리 내어 읽어 보고
   어색하면 고치세요.
2. **한 줄은 한 사람이 한 번에 하는 말입니다.** 한 줄이 세 문장을 넘으면
   듣는 사람이 못 따라갑니다 (안내 방송·강연은 예외).
3. **남자와 여자를 반드시 갈라 쓰세요.** 듣기 문항의 절반이 「여자는
   무엇을 합니까」입니다. 누가 무엇을 말했는지가 문제의 핵심입니다.
4. **정답의 근거가 대본 안에 또렷하게 있어야 합니다.** 짐작해야 풀리는
   문항은 좋은 문항이 아닙니다.
5. 사람 이름은 민수·수미·지영·현우처럼 흔한 것으로. 실존 인물, 실제
   상호, 실제 지명(서울·부산 정도는 괜찮음)은 피하세요.

### 오답 만드는 법 — 여기서 문항의 값이 갈립니다

나쁜 오답은 「딱 봐도 아닌 것」입니다. 그러면 대본을 안 듣고도 풀립니다.
좋은 오답은 이렇게 만듭니다.

- **대본에 나온 말을 쓰되 관계를 틀리게** — 남자가 한 일을 여자가 한
  것으로, 다음 주에 할 일을 이미 한 것으로.
- **한 낱말만 어긋나게** — 「작아서 바꾼다」 ↔ 「커서 바꾼다」.
- **대본에 아예 없는 말** 은 넷 중 하나만.

넷 다 대본을 듣고 나면 하나만 맞아야 하고, **안 듣고는 못 고르게** 하세요.

### 절대 하면 안 되는 것

- **보기 중에 뜻이 같은 것 두 개** — 답이 둘이 됩니다.
- **해설에 「1번」「②」처럼 번호 쓰기** — 보기 순서는 나중에 바뀝니다.
  반드시 보기의 **글자를 그대로 인용**하세요.
  (○) 「"학교에 가요"가 맞습니다」 (✗) 「3번이 맞습니다」
- **발문과 대본이 어긋나기** — 「여자의 중심 생각」을 물으면서 대본에
  여자가 안 나오면 그 문항은 풀 방법이 없습니다.
- **그림이 있어야 하는 유형 만들기** — 우리는 그림을 못 넣습니다.
- **정답을 한 자리에 몰기** — 아래 「정답 자리」를 반드시 지키세요.

### 정답 자리

`answer` 는 0부터 셉니다(0=첫째 보기). **넷에 고르게 흩으세요.**
문항을 다 만든 뒤 세어 보고, 한 자리가 40% 를 넘거나 한 번도 안 나온
자리가 있으면 보기 차례를 바꿔서 맞추세요. 몰리면 학습자가 내용 대신
자리를 외웁니다.

### 급수

| 급수 | 어휘·문법 | 대본 길이 |
|---|---|---|
| 1급 | 기초 낱말, -아/어요, -았/었어요, 안/못 | 1~2줄, 줄마다 10자 안팎 |
| 2급 | 생활 낱말, -(으)려고, -아/어서, -지만, -(으)ㄹ 거예요 | 2~4줄 |
| 3급 | 사회생활, -는데, -기로 하다, -아/어 놓다 | 3~5줄 |
| 4급 | 추상어 조금, -더라고요, -게 되다, -는 바람에 | 4~6줄 |
| 5급 | 시사·전문어, -(으)ㄴ 셈이다, -기 마련이다 | 6~10줄, 강연·대담 |
| 6급 | 논설·학술, 함축과 태도 | 8~12줄 |

### 낼 수 있는 유형

**TOPIK I (1·2급)**

| type | 무엇을 묻나 | 대본 |
|---|---|---|
| `reply` | 물음에 맞는 대답 | 한 줄 (묻는 말) |
| `follow` | 이어지는 말 (인사·사과·감사) | 한 줄 |
| `place` | 여기는 어디입니까 | 두 줄 대화 |
| `topic` | 무엇에 대해 이야기합니까 | 두 줄 대화 |
| `detail` | 들은 내용과 같은 것 | 세네 줄 대화 |
| `main` | 남자/여자의 중심 생각 | 두 줄, 한쪽이 길게 |
| `long` | 긴 담화 — **한 대본에 두 문제** | 안내 방송이나 네 줄 이상 대화 |

**TOPIK II (3~6급)**

| type | 무엇을 묻나 |
|---|---|
| `follow` | 이어지는 말 |
| `act` | 이어서 할 행동 (누가 무엇을 하기로 했나) |
| `detail` | 들은 내용과 같은 것 |
| `main` | 중심 생각 |
| `long` | 긴 담화 — 한 대본에 두 문제 |

`long` 은 **두 문항이 짝**입니다. `pair` 에 같은 이름을 주고 `script` 를
**글자 하나까지 똑같이** 두 번 적으세요. 한 번 들려주고 두 문제를 내는
자리이므로 대본이 다르면 안 됩니다. 두 문제는 서로 다른 것을 물어야
합니다 — 보통 하나는 중심 생각/화제, 하나는 세부 내용입니다.

### 내보낼 모양

JSON 배열 하나만 보내세요. 설명이나 ```json 표시 없이 배열만.

```
[
  {
    "id": "lI-31",
    "exam": "I",
    "slot": 17,
    "grade": 2,
    "type": "detail",
    "script": [
      { "who": "w", "text": "민수 씨, 내일 등산 같이 갈래요?" },
      { "who": "m", "text": "가고 싶은데 내일은 회사에 가야 해요. 다음 주 토요일은 어때요?" },
      { "who": "w", "text": "좋아요. 그럼 다음 주에 가요." }
    ],
    "q": "들은 내용과 같은 것을 고르십시오.",
    "options": [
      "두 사람은 내일 등산을 갑니다.",
      "남자는 등산을 싫어합니다.",
      "두 사람은 다음 주에 등산을 갑니다.",
      "여자는 내일 회사에 갑니다."
    ],
    "answer": 2,
    "why": "남자가 내일은 회사 때문에 안 되니 다음 주 토요일을 말했고 여자가 「좋아요」라고 했습니다. 회사에 가는 사람은 남자입니다."
  }
]
```

밭 설명:

- `id` — 내가 주문서에서 지정합니다. 그대로 쓰세요.
- `exam` — `"I"` 또는 `"II"`
- `slot` — 흉내 내는 실제 시험의 문항 번호. 주문서에 적힌 것을 쓰세요.
- `grade` — 급수 (I 은 1·2, II 는 3~6)
- `who` — `"m"` 남자 · `"w"` 여자 · `"n"` 안내 방송이나 독백
- `answer` — 0부터. 정답인 보기의 자리
- `why` — **한국어로**, 왜 그것이 답이고 다른 것이 왜 아닌지. 두세 문장.
  보기의 글자를 그대로 인용할 것.

`q` 와 `options`, `script` 는 전부 한국어입니다. 영어를 섞지 마세요.

### 다 만든 뒤 스스로 확인할 것

배열을 내보내기 전에 직접 세어 보고 답하세요 (JSON 앞에 짧게 적으세요).

1. `answer` 가 0·1·2·3 각각 몇 개인가? 한쪽이 40% 를 넘지 않는가?
2. 발문이 「남자」를 묻는 문항마다 대본에 `"who": "m"` 이 있는가? 「여자」도 마찬가지.
3. `pair` 로 묶은 두 문항의 `script` 가 글자까지 같은가?
4. 한 문항 안에 뜻이 같은 보기가 둘 있지 않은가?
5. `why` 에 「1번」이나 「②」 같은 번호가 들어가지 않았는가?

## 주문서 (이 부분만 바꿔서 붙인다)

```
이번에 만들 것:

  시험    : TOPIK I
  유형    : detail (들은 내용과 같은 것)
  자리    : 17~21번
  급수    : 2급
  개수    : 10문항
  id      : lI-31 부터 lI-40 까지 차례로

소재는 서로 겹치지 않게 하세요. 이미 만든 것: 등산 약속, 옷 교환,
영화 시간, 음식 취향, 방학 계획.
```

「이미 만든 것」은 꼭 적으세요. 안 적으면 열 문항 중 서넛이 「약속을
미루는 대화」로 나옵니다.

## 받은 뒤에 할 일

1. `topik-listening.js` 의 해당 배열 끝에 붙인다. **id 는 절대 안 바꾼다** —
   진도가 id 로 묶여 있다.
2. `node tools/check-listening.mjs` — 정답 쏠림, 발문·대본 어긋남, 짝
   대본 불일치, 번호 인용을 전부 잡는다.
3. 검사기가 조용하면 사람이 읽는다. 기계가 못 보는 것 하나만 보면 된다 —
   **한국 사람이 실제로 그렇게 말하는가.**
4. `node tools/tts-manifest.mjs` → `node tools/tts-build.mjs` 로 소리를
   굽는다. 새로 넣은 문항만 구워진다.
