# 안티 그래비티 작업 지시 — TOPIK 쓰기 문항 늘리기

> 이 파일 전체를 안티 그래비티에 붙여 넣는다.

## 왜

TOPIK 쓰기 문항이 58개(51번 20 · 52번 17 · **53번 11 · 54번 10**)다. 53·54번은 이제 **AI 채점**
(`supabase/functions/grade-writing`)이 붙어서, 학생이 가장 많이 연습할 곳인데 문항이 모자란다.
AI 채점은 문항의 `points`(채점 포인트) · `model`(모범답안) · `samples`(점수를 매긴 예시 답안)를
**그대로 채점 기준으로 쓴다.** 이 칸이 부정확하면 채점이 틀린다 — 그래서 이번 일은 양보다 정확성이다.

**목표**
- 53번 11 → **30**, 54번 10 → **30** (새로 19 · 20개)
- 51번 20 → **30**, 52번 17 → **30**
- 이미 있는 `w54-2` · `w54-3` 에 빠진 **「하」 예시 답안**을 채운다

## 순서

```bash
git checkout main && git pull origin main
git checkout -b topik-writing-more
node tools/check-writing.mjs      # 지금 상태 (짚어 둘 것 2건: w54-2 · w54-3)
```

`topik-writing.js` 의 `TW_ITEMS` 에 더한다. **같은 번호끼리 모아서**, id 는 그 번호의 다음 수
(`w53-12`, `w53-13` …). 모양은 이미 있는 문항을 그대로 따른다 — `w53-1` · `w54-1` · `w51-1` 을 먼저 읽는다.

## 번호마다 반드시 있어야 하는 것

**51 · 52번** — `blanks` 둘(`㉠` · `㉡`), 지문에 `( ㉠ )` · `( ㉡ )` 자리, 빈칸마다 `answers` 2~3개와 `point`.
51번은 실용문(안내 · 초대 · 문의 · 공지, `register: 'formal'`), 52번은 설명문(`register: 'plain'`).

**53번** — 표 · 그래프 설명 200~300자.
- `data` 셋 이상(조사 기관 · 대상 · 수치 변화 · 원인/전망), `tasks` 셋, `min: 200, max: 300`, `register: 'plain'`
- `points` 셋(content · structure · language), `deduct` 셋 이상
- `model` **200~300자**(검사기가 센다), `-(느)ㄴ다체`
- `samples` **상 · 중 · 하 차례로 셋**, `total` 은 0~30, **상 > 중 > 하**. `why` 에 왜 그 점수인지 한두 문장

**54번** — 논술 600~700자. 53번과 같고, `data` 대신 `tasks` 셋, `min: 600, max: 700`, `total` 0~50.

## 예시 답안(samples) 쓰는 법 — 가장 중요

AI 는 이 셋을 보고 **점수의 눈높이**를 맞춘다.
- **상**(53번 26~29 · 54번 44~49): 과제를 다 채우고 문단 · 연결이 자연스럽고 문체가 한결같다
- **중**(53번 17~22 · 54번 28~35): 과제는 거의 채웠지만 문단을 안 나누거나, 어휘가 단순하거나, 문체가 한두 번 섞인다
- **하**(53번 8~14 · 54번 12~22): 분량이 모자라거나, 과제를 빠뜨리거나, 해요체로 쓰거나, 문법 오류가 잦다
- 「중」 · 「하」는 **실제 학습자가 쓸 법한 실수**를 넣는다(조사 빠뜨림 · -습니다 섞임 · 같은 말 되풀이). 일부러
  엉터리로 쓰지 않는다.
- 점수 계산은 실제 TOPIK 배점을 따른다 — 53번 = 내용 및 과제 수행 7 · 글의 전개 구조 7 · 언어 사용 16,
  54번 = 12 · 12 · 26.

## 주제

- 53번: 통계 · 설문(1인 가구 · 전기차 · 온라인 수업 · 외국인 관광객 · 반려동물 · 재택근무 …) — 이미 있는
  주제와 겹치지 않게. 수치는 **그럴듯하되 지어낸 것**이라 실제 기관 이름을 쓰지 않는다(「한국통계연구원」처럼 가상).
- 54번: 사회 · 교육 · 기술 · 환경 · 직업(인공지능과 일자리 · 칭찬의 효과 · 조기 교육 · 소비 습관 …).
  질문 셋은 「의미/중요성 → 문제/원인 → 해결/노력」 흐름.

## 다 쓰면

```bash
node tools/check-writing.mjs     # 「고쳐야 할 것」 0, 짚어 둘 것에 w54-2 · w54-3 이 빠져야 한다
node tools/check-courses.mjs && node tools/check-geo.mjs
node tools/build-pages.mjs       # topik-writing/ 쪽과 AI 채점용 items.json 이 새로 생긴다
node tools/stamp.mjs && node tools/stamp.mjs --check
git add -A && git commit -m "topik writing: 53·54 to 30 each, 51·52 to 30, samples for w54-2/3"
git push -u origin topik-writing-more
```

`check-geo` 가 멈추면 **첫 쪽 · llms.txt 의 쓰기 문항 수**가 옛 값이라는 뜻이다 — 검사기가 말하는 값으로
`index.html` 과 `llms.txt` 를 고친다(「TOPIK 쓰기 58」 → 새 수, 「TOPIK 문항 917」 → 새 합).

## 하지 말 것

- `tools/` 의 도구를 고치지 않는다. 검사기를 통과시키려고 검사기를 바꾸지 않는다.
- 이미 있는 문항의 id 를 바꾸지 않는다(학생 기록이 id 에 붙어 있다).
- `stamp.mjs --check` 를 건너뛰지 않는다.
- 여러 번 나눠 해도 된다 — 번호 하나(예: 53번 19개) = 커밋 하나.

PR 설명에 번호별 전 → 후 수와 `check-writing` 결과를 적는다.
