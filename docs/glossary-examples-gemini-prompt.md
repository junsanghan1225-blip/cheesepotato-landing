# 국어사전 예문 만들기 — Gemini 에게 주는 지시문

국립국어원 자료(docs/glossary-krdict.json)에는 뜻풀이·번역만 있고 **예문
(용례)이 아예 없다.** 지어내지 않는다는 원칙(gloss-find.js: "틀린 뜻을
내주느니 빈 칸을 내준다")대로, 없는 예문을 화면에 채워 넣지 않고 대신
Gemini 로 새로 짓고 사람이 검수하는 절차를 둔다 — TOPIK 문항·듣기 대본과
같은 방식이다.

한 번에 **40낱말씩** 시킨다. 한 번에 다 시키면(4,047개) 뒤로 갈수록
성의가 빠지고, 문장이 서로 비슷해지고, 검토할 양도 감당이 안 된다.

아래 「보낼 글」을 그대로 복사해 붙이고, 맨 아래 **주문서**만 그때그때
`node tools/glossary-examples-prompt.mjs` 로 새로 뽑아 바꿔 끼운다. 받은
JSON 은 그대로 파일에 저장해 `node tools/add-glossary-examples.mjs`로
넣고, 반드시 `node tools/check-glossary-examples.mjs`를 돌린다.

---

## 보낼 글 (여기부터 복사)

당신은 한국어를 외국어로 가르치는 경험이 많은 한국어 교육 전문가입니다.
아래 낱말마다 **예문 하나씩**을 새로 지어 주세요.

### 예문을 쓰는 법

1. **해요체로 씁니다.** "저는 학생이에요", "밥을 먹어요"처럼 친근하고
   격식 없는 존댓말입니다. 문어체(-습니다)나 반말(-어)로 쓰지 마세요.
2. **한 문장, 한 절입니다.** 접속사로 두세 문장을 이어 붙이지 마세요.
   짧고 또렷한 문장 하나가 처음 배우는 사람에게 맞습니다.
3. **그 낱말이 실제로 쓰이는 자리에 넣습니다.** 활용형(먹다→먹어요,
   조용하다→조용해요)으로 써도 됩니다 — 사전에 오르는 기본형 그대로
   박아 넣을 필요는 없습니다.
4. **문장 속 다른 낱말은 최대한 쉬운 말로 고릅니다.** 이 예문은 그
   낱말 하나를 익히려고 보는 것이지, 예문 속 다른 낱말까지 새로
   가르치려는 것이 아닙니다. 대상 낱말보다 어려운 낱말을 섞지 마세요.
5. **뜻풀이(주문서에 같이 드립니다)에 맞는 뜻으로 씁니다.** 한 낱말에
   뜻이 여럿일 때(가격 = 때림 / 물건값) 엉뚱한 뜻으로 예문을 쓰면
   학습자가 잘못 외웁니다.
6. **실존 인물·상호·사건을 지어내지 않습니다.** 사람 이름은 준상·리아·
   주리·석진처럼 흔한 것으로, 장소는 "학교", "회사", "공원"처럼
   일반적인 곳으로 씁니다. 서울·부산 정도의 지명은 괜찮습니다.
   반려동물(강아지·고양이 등)이 예문에 등장하면 이름은 치즈나 감자를
   씁니다 — 사람 이름 자리에 넣지 말고 반려동물에만 씁니다.
7. **번역은 뜻을 옮기지 문장을 그대로 옮기지 않습니다.** 자연스러운
   영어 문장이면 됩니다.

### 절대 하면 안 되는 것

- **문법 설명을 예문에 끼워 넣기** — "먹다는 동사입니다" 같은 것은
  예문이 아니라 설명입니다.
- **대상 낱말을 안 쓰기** — 예문에 반드시 그 낱말(또는 활용형)이
  들어가야 합니다.
- **거짓·자극적인 내용** — 통계·수치·사건을 지어내거나, 폭력·혐오·
  선정적인 내용을 넣지 마세요. 일상적이고 평범한 문장이면 됩니다.

### 내보낼 모양

JSON 배열 하나만 보내세요. 설명이나 ```json 표시 없이 배열만.

```
[
  { "head": "가격", "ex": "이 가방은 가격이 얼마예요?", "en": "How much is this bag?" },
  { "head": "먹다", "ex": "아침에 뭐 먹었어요?", "en": "What did you eat this morning?" }
]
```

- `head` — 주문서에 적힌 표제어와 **글자까지 그대로** 같아야 합니다.
  받은 순서·개수도 주문서와 같아야 합니다(뺴거나 더하지 마세요).
- `ex` — 해요체 예문 한 문장. 반드시 그 낱말(또는 활용형)을 포함합니다.
- `en` — 그 예문의 영어 번역 한 문장.

### 다 만든 뒤 스스로 확인할 것

배열을 내보내기 전에 직접 세어 보고 답하세요 (JSON 앞에 짧게 적으세요).

1. 주문서에 있던 낱말 수와 배열 길이가 같은가?
2. 모든 예문이 해요체로 끝나는가? (-습니다, -어/아 로 끝나지 않는가)
3. 예문마다 그 낱말(또는 자연스러운 활용형)이 실제로 들어 있는가?
4. 뜻풀이에 준 뜻과 다른 뜻으로 쓴 예문이 없는가?
5. 실존하는 사람·상호·통계를 지어내지 않았는가?

## 주문서 (이 부분만 바꿔서 붙인다)

`node tools/glossary-examples-prompt.mjs` 를 돌리면 아직 예문이 없는
낱말 40개와 그 뜻풀이·품사를 골라 여기 붙일 표를 그대로 뽑아 준다.
그 출력을 통째로 복사해 위 "보낼 글" 뒤에 붙이면 된다.

## 받은 뒤에 할 일

```
node tools/add-glossary-examples.mjs 받은것.json
node tools/check-glossary-examples.mjs
node tools/build-glossary-examples.mjs
```

1. `add-glossary-examples.mjs` — 모양을 검사하고(개수·표제어 일치·
   해요체 여부·낱말 포함 여부) `docs/glossary-examples.json` 에 넣는다.
   `docs/glossary.json`처럼 사람이 검토한 원본이다.
2. `check-glossary-examples.mjs` — 지금까지 쌓인 예문 **전체**를 다시
   훑어 중복 문장, 대상 낱말보다 어려운 낱말 섞임, 표제어 불일치 같은
   것을 잡는다. `add-glossary-examples.mjs`는 이번에 받은 것만 보고
   이 도구는 전체를 본다 — 두 도구가 보는 범위가 다르다.
3. `build-glossary-examples.mjs` — `docs/glossary-examples.json` 을
   화면이 읽는 `glossary-examples.js` 로 굽는다. `glossary-senses.js`
   처럼 국어사전 화면을 열 때만 따로 받는다.
4. `node tools/stamp.mjs` 로 자국을 새로 찍고 커밋한다.

검사기가 조용하면 사람이 마지막으로 한 번 눈으로 훑는다. 기계가 못 보는
것 하나만 보면 된다 — **한국 사람이 실제로 그렇게 말하는가.**
