# 안티 그래비티 지시서 — TOPIK 읽기 모의고사 4회분 → 8회분

> ⚠ 2026-10-07: 이 지시서는 `docs/antigravity-topik-balance-task.md`(읽기 10 · 듣기 6) 가 **대신한다** — 이것은 쓰지 않는다.

브랜치: `topik-mock-more` (main 에서 새로). 고칠 파일: `topik.js`(TOPIK I 읽기) · `topik2.js`(TOPIK II 읽기)의 문항 배열에 **문항만 보탠다**.
도구(`tools/`) · 다른 파일은 손대지 말 것. 모든 문항은 **창작** — 실제 기출 · 교재 문항을 옮기거나 살짝 바꾸지 않는다. 사람 · 회사 이름, 정확한 통계 · 법 · 요금 같은 「사실」은 지어내지 않는다.

## 왜
모의고사 회차는 「번호(slot)마다 가진 문항 수」 가운데 가장 적은 수만큼 나온다(지금 4개 → 4회분). 모든 번호를 **8개**로 채우면 8회분이 된다.

## 채울 수(번호 : 지금 → 8)
- TOPIK I 읽기(`topik.js` TOPIK_READING): 31~33 · 49~56 · 59~70 은 4개 → **4개씩 더**, 34~37 · 42 는 6개 → **2개씩 더**, 38~41 · 43~45 · 57 · 58 은 7개 → **1개씩 더**(46~48 은 이미 8개).
- TOPIK II 읽기(`topik2.js` TOPIK2_READING): 1~4 · 32~50 은 4개 → **4개씩 더**(5~31 은 이미 19개).

## 지킬 것
- 문항 모양은 같은 번호의 기존 문항과 **똑같이**: `exam, id, grade, slot, type, genre, topic, passage, question, options(4개), answer(0~3), why(한국어 해설)`.
  `id` 는 그 파일의 규칙대로 이어서(겹치지 않게). `type` · `genre` 는 그 번호의 다른 문항과 같게.
- **한 지문에 두 문제**인 번호(예: 49-50, 51-52 …)는 같은 지문으로 두 문항을 **짝으로** 만든다 — 기존 짝 문항의 `pair` 칸 쓰는 법을 그대로 따른다.
- 정답 위치(①~④)가 한쪽에 몰리지 않게 고루. 오답도 그럴듯하게, 정답은 하나만.
- `why` 는 왜 그 답인지 1~2문장(다른 보기가 왜 틀렸는지도 짧게).

## 확인 · 끝나면
`node tools/check-topik.mjs` 가 통과해야 한다. 통과하면 `topik.js` · `topik2.js` 만 커밋 · 푸시. 자국(stamp)은 Claude 가 main 기준으로 다시 찍는다.
듣기 모의고사 늘리기는 따로 지시서를 쓴다(그림 문항이 있어 방식이 다르다).
