# 레슨 대격변 — 레슨 방식 개별화 (운영자 2026-10-15 「문법이나 ○○별로 조금 개별화해서 레슨 방식을 더 개별화해 학습의 질을 올리자」, 뜻은 「둘 다」)

> 상태: **계획 — 운영자 확인 전.** 확인되면 1단계부터 PR 하나씩. 앞서 한 「레슨별 새 블록」(`course-blocks.md`)은 **재료**를 늘리는 일, 이 계획은 그 재료를 **어떤 순서 · 방식으로 먹이는가**를 바꾸는 일이다.
> ⚠ 운영자가 말해 주지 않은 것: 「별로」 앞의 낱말(문법이나 ○○), 「Learn by course」 메뉴 구조를 어떻게 바꿀지(코스 목록 · 길). 아래 「물어볼 것」.

## 지금 모양 (사실)
- 레슨 401개 = 코스 97개 × 보통 4레슨. 모든 레슨이 거의 같은 틀: 읽는 블록(글 · 메모) 몇 장 → 푸는 문제 몇 개 → 끝. (`flow()` 가 차례로 낸다)
- 코스 종류: 한글(11) · 첫 낱말(8) · 문법 핵심(8) · 초급 `bg-*`(문법 33 + 대화 5 + 불규칙 2) · 중급 `im-*` · 고급 `ad-*`(뉘앙스).
- 학생 정보는 이 기기에 이미 있다: 틀린 문제(`cp-wrong-v1`) · 자기 점검 「아직이에요」(`cp-cando-v1`) · 이어 하기(`cp-lesson-resume`) · 진도.

## 방향 A — 종류별 틀 (레슨이 무엇을 가르치는지에 따라 흐름이 다르다)
같은 「읽기 → 문제」가 아니라 종류마다 처방:
| 종류 | 흐름(처방) |
|---|---|
| 한글 | 소리 듣기 → 따라 쓰기 느낌의 고르기 → 비슷한 소리 구분(listen) → 낱말 읽기 → 점검 |
| 낱말(first-words) | 낱말 카드(vocab) → 듣고 고르기 → 뜻 맞히기 → 받아쓰기 → 짧은 문장 만들기 → 내 단어장 |
| 문법(bg · grammar-core) | 한 줄 목표 → 예문 3개 보기 → **비교(헷갈리는 짝)** → 활용 표(conj) → 바꾸기 → 문장 만들기 → 내 문장 쓰기 → 점검 |
| 대화(bg-d) | 장면 듣기(passage) → 역할 고르기 → 빈칸 → 따라 말하기(speak) → 내 대답 쓰기 |
| 불규칙 | 규칙 한 장 → 활용 표 → 오류 찾기 → 섞어 연습 |
| 뉘앙스(im · ad) | 상황 → 비교 → 오류 찾기 → 상황에 맞는 말 고르기 → 내 문장 |
구현: 레슨 종류(코스 id 규칙)마다 **처방 순서표**(`LESSON_RECIPE`)를 두고, 합친 블록들을 그 순서로 정렬 · 단계 막대(① 배우기 ② 연습 ③ 써 보기 ④ 점검)를 위에 보인다. 블록 자료는 그대로(`courses*.js` · `lesson-extra/`).

## 방향 B — 학생별 맞춤 (같은 레슨도 사람마다 다르게)
1. **레슨 시작 「빠르게 / 차근차근」** — 빠르게는 문제 약 절반(쉬운 것 건너뜀), 차근차근은 전부. 마지막 고름을 기억.
2. **틀리면 같은 레슨 안에서 한 번 더** — 틀린 문제와 같은 종류 · 같은 레슨의 다른 문제를 뒤에 1~2개 끼워 넣는다(`lsQueue`). 맞히면 넘어간다.
3. **첫 세 문제 진단** — 시작 세 문제를 모두 맞히면 「이미 아는 것 같아요. 점검만 할까요?」로 압축(건너뛴 레슨은 진도 인정 여부는 운영자 결정).
4. **복습 간격** — 끝낸 레슨의 문제를 1 · 3 · 7일 뒤에 「지난 시간 복습」에 넣는다(지금은 무작위 3개).
5. **내 약점 모음** — 틀림 · 「아직이에요」를 문법 갈래(조사 · 시제 …)로 모아 「오늘의 한 가지」 추천(오늘 할 일 · 오답 노트에 한 줄).
6. (나중) 서버 저장 — 지금은 이 기기에만. 로그인한 사람은 기기를 바꿔도 이어지게(표 필요 → SQL 파일, 운영자 실행).

## 지킬 것
- 원래 레슨 id · 블록은 바꾸지 않는다(진도 열쇠). 처방은 **순서와 끼워 넣기**만.
- 기출 아님 · 사실 안 지어냄. 학생 정보는 기기 안(서버로 안 보낸다 — 6단계 전까지).
- 결제 · 비밀 값 · Supabase 직접 손대기 없음.
