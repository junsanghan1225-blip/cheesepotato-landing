# 문법 섹션 — 위에서부터 다시 짜기 (초안, 2026-10-01)

> 운영자 요청: 「예문 만들기」를 **문법** 섹션으로. 블록으로 맞추기 → 직접 써서 검사(맞춤법 검사기 느낌).
> 연구를 바탕으로 문법을 잘 배우는 길을 탑다운으로, 같이 알면 좋은 단어, 실제로 쓰인 모습(TOPIK 등), 이미지.
> 이 문서는 **제안**이다. ✅ 는 이미 만든 것, 나머지는 운영자가 정한 뒤에 만든다.

## 0. 한 줄 요약

문법 하나를 **「알아보기 → 이해하기 → 맞추기 → 바꾸기 → 내 문장 → 다시 만나기」** 여섯 걸음으로 돌린다.
화면은 이 순서대로 위에서 아래로 내려가고, 그림은 모든 표현이 아니라 **그림이 뜻을 바꿔 주는 표현부터** 넣는다.

## 1. 연구가 말하는 것 (근거)

아래는 제2언어 습득 연구에서 널리 받아들여진 결과들이다. 논문 요지를 일반적으로 옮긴 것이고,
이 세션에서 원문을 다시 읽지는 않았다 — 문서 · 마케팅에 인용할 때는 원문을 확인한다.

| 근거 | 요지 | 우리 화면에서 |
|---|---|---|
| 명시적 교수 메타분석 (Norris & Ortega 2000; Spada & Tomita 2010) | 규칙을 분명히 알려 주는 수업이 효과가 크고 오래간다 | 뜻 · 형태 · 주의할 점을 먼저 짧게 보여 준다 (있음) |
| 알아차림 가설 (Schmidt 1990) · 입력 강조 (Sharwood Smith) | 눈에 띄어야 배운다 | 예문에서 그 문법 부분에 **색을 칠한다** |
| 처리 교수 (VanPatten) | 형태를 만들기 전에, 뜻을 보고 형태를 **골라 보는** 연습이 먼저 | 「어느 문장이 그림과 맞아요?」 고르기 |
| 출력 가설 (Swain 1985) | 직접 말하고 써 봐야 모르는 곳이 드러난다 | 블록 맞추기 ✅ · 내 문장 쓰기 ✅ |
| 기술 습득 이론 (DeKeyser) | 아는 것(선언) → 할 수 있는 것(절차) → 저절로(자동화), 연습량이 다리 | 조립 → 바꾸기 → 자유 쓰기로 점점 풀어 준다 |
| 교정 피드백 메타분석 (Lyster & Saito 2010 등) | 틀린 곳을 바로 짚어 주면 는다 | 맞춤법 · 띄어쓰기 검사 ✅, 블록의 빨간 칸 ✅ |
| 인출 연습 (Roediger & Karpicke 2006) · 간격 반복 (Cepeda 외 2006) | 다시 읽기보다 **꺼내 보기**, 한 번에 몰기보다 **며칠 뒤 다시** | 오답 노트 · 오늘 카드에 문법 복습을 끼운다 |
| 이중 부호화 (Paivio) · 멀티미디어 학습 (Mayer) | 말과 그림을 함께 주면 더 잘 기억한다. 단, 꾸미기용 그림은 오히려 방해 | 그림은 **뜻을 보여 주는 곳에만** (아래 5) |
| 어휘 덩어리 (Lewis 1993; Nation) | 문법은 늘 같이 다니는 말과 한 덩어리로 외울 때 빨리 쓴다 | 「같이 알면 좋은 단어」 (아래 4) |

## 2. 표현 하나의 화면 — 여섯 걸음

| 걸음 | 무엇을 | 상태 |
|---|---|---|
| 1. 알아보기 | 뜻 · 형태 · 주의 + **장면 그림 한 장** + 예문의 문법 부분 색칠 | 색칠 ✅ (2026-10-01, 꼴이 한 글자뿐인 표현은 안 칠함), 그림은 새로 |
| 2. 이해하기 | 그림(또는 상황 한 줄)을 보고 맞는 문장 고르기 — 둘 중 하나 | 새로 |
| 3. 맞추기 | 예문을 블록으로 맞추기 | ✅ (2026-10-01) |
| 4. 바꾸기 | 「먹다 + -(으)면서 → ?」 기본형을 문법에 맞게 바꿔 쓰기 | ✅ (2026-10-01) 195개 표현 · `ko-conj.mjs` attach(정답표 58개) → `build-grammar-drill.mjs`. 조사 · 인용 · 문체 · 피동/사동 등 95개는 문항 없음 |
| 5. 내 문장 | 직접 써서 「검사」 — 맞춤법 · 띄어쓰기(뜻은 안 봄) → 게시판에 올리기 | ✅ (2026-10-01) |
| 6. 다시 만나기 | 3 · 4에서 틀린 것은 오답 노트로, 며칠 뒤 오늘 카드에 다시 | 오답 노트 연결만 하면 된다 |

## 3. 실제로 이렇게 쓰인다 — 「쓰임 보기」

말하기 섹션에 묶이지 않고, **우리 자료 전체에서** 그 문법이 들어간 문장을 찾아 보여 준다:
TOPIK 읽기 · 듣기 대본, 쓰기 모범답안, 읽기 지문, 코스 대화, 사전 예문(약 1만 개).

- 방법: 표현마다 찾을 꼴(예: `-(으)면서` → 「면서」로 끝나는 어절)을 적어 두고 도구가 찾아 모은다 → 사람이 한 번 훑어 틀린 것(「면서」가 다른 뜻인 경우)을 뺀다.
- 화면: 「TOPIK 읽기 43번에서 · 이렇게 쓰였어요」처럼 출처와 함께 2~3개, 누르면 그 문항으로.
- 좋은 점: 새로 지어낼 필요가 없고, 「시험에 이렇게 나온다」가 바로 보인다.

## 4. 같이 알면 좋은 단어

표현마다 **같이 자주 다니는 낱말 3~5개**와 짧은 예 — 예: `-(으)ㄴ 적이 있다` + 가 보다 · 먹어 보다 · 한 번도.
지금 자료의 「자주 함께 쓰는 말」 칸이 이 자리의 씨앗이다. 양이 많아서(290개) **안티 그래비티**에게 맡기고,
우리 낱말 사전에 있는 말은 사전 쪽으로 이어 준다(TOPIK 급수 배지까지).

## 5. 그림 — 내 생각

**그림은 넣는 것이 맞다. 다만 290개 전부가 아니라, 그림이 뜻을 바꿔 주는 것부터.**

1. **그림이 가장 잘 먹히는 곳**
   - 장면이 곧 뜻인 것: `-고 있다` vs `-아/어 있다`(입고 있다 · 앉아 있다)
   - 헷갈리는 짝: `-아서` vs `-(으)니까`
   - 때 · 순서: `-기 전에` · `-(으)ㄴ 후에` — 이것은 그림보다 **시간 막대(SVG)** 가 더 정확하다. 자료에서 그대로 그릴 수 있어 싸고 늘 선명하다.
2. **지켜야 할 것**
   - 그림 안에 한국어 글자를 넣지 않는다 — 생성 이미지는 한글을 자주 망가뜨린다. 글은 늘 화면(HTML)에 얹는다.
   - 치즈 · 감자 캐릭터로 **한 가지 그림체**. 스타일 설명서(색 · 선 · 배경 · 구도)를 먼저 정하고 모든 요청에 붙인다.
   - 무게: webp · 가로 800px 안팎 · 늦게 불러오기(lazy). 한 장 50KB 안쪽.
   - 권리: 쓰는 생성 도구의 이용 약관이 상업적 사용을 허락하는지 운영자가 확인한다. 실존 인물 · 브랜드는 넣지 않는다.
   - 검수: 그림이 문법의 뜻과 정말 맞는지 사람이 본다(손가락 개수보다 이게 중요하다).
3. **누가 만드나** — Claude 는 그림을 만들 수 없다. Claude 가 **그림 지시서**(스타일 설명서 + 표현마다 장면 한 줄)를 쓰고,
   운영자 또는 안티 그래비티가 생성 도구로 만든 뒤 올리면 Claude 가 검토해 넣는다.
4. **순서** — 초급 핵심 30개로 먼저 시험 → 블록 · 고르기 정답률과 머문 시간을 비교 → 효과가 보이면 넓힌다.
