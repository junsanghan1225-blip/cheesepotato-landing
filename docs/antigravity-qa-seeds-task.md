# 안티 그래비티 작업 — 「묻고 답하기」 씨앗 질문 30개

> 배경: `docs/community-plan.md` 6단계 4 — 게시판이 비어 있으면 아무도 먼저 안 쓴다.
> 학습자가 실제로 자주 묻는 질문과 **운영자 답 초안**을 미리 채워 둔다. Claude 가 검토하고, 운영자가 읽고 고친 뒤 사이트에 올린다.
> 사이트 화면: 「묻고 답하기」(#learn/qna) — 지식iN 처럼 질문 → 답 → 채택. 답은 지금 운영자만 단다.

## 할 일

1. **꼭 새로 받은 main 에서**: `git fetch origin && git checkout -b qa-seeds origin/main`
2. 새 파일 **`docs/qa-seeds.json` 하나만** 만든다(아래 모양). 질문 **30개**.
3. 검사: `node -e "const a=JSON.parse(require('fs').readFileSync('docs/qa-seeds.json','utf8'));console.log(a.length)"` → `30`
4. `git add docs/qa-seeds.json && git commit -m "qa seeds: 30" && git push -u origin qa-seeds`

PR 은 열지 않는다 — Claude 가 검토하고 연다. **`git push` 까지 꼭 한다.**

## 게시판별 개수

| board | 게시판 | 개수 | 이런 질문 |
|---|---|---|---|

| `words` | 낱말 · 표현 | 7 | 「알다 vs 모르다」 대답법, 「보다 · 구경하다 · 관람하다」, 「아까 · 이따가」, 「괜찮아요」의 여러 뜻, 「수고하세요」를 언제 쓰나 … |
| `topik` | TOPIK | 5 | 쓰기 53번 그래프 글 구성, 54번 글 개요 짜는 법, 듣기에서 놓쳤을 때, 읽기 시간 모자랄 때, 단어는 몇 개쯤 외우나 |
| `speak` | 발음 · 말하기 | 4 | 받침 뒤 연음(「음악이」), 「ㅓ / ㅗ」 구분, 「감사합니다」의 [함니다], 처음 만난 사람에게 말 걸기 |
| `life` | 한국 생활 | 4 | 식당에서 부르기(「여기요」), 나이 · 호칭(「언니 · 형 · 선배님」), 카톡 말투(「ㅋㅋ · ㅎㅎ」), 편의점 · 카페에서 쓰는 말 |

## 파일 모양

```json
[
  {
    "board": "grammar",
    "title": "-아서/어서 and -(으)니까 — what's the difference?",
    "body": "Both mean 'because', right? 늦어서 미안해요 is OK but 늦으니까 미안해요 sounds strange to my Korean friend. Why?",
    "answer": "둘 다 「이유」를 말하지만 쓰임이 달라요.\n\n① -아서/어서: 자연스러운 까닭. 뒤에 명령 · 권유(-세요 · -(으)ㅂ시다)가 못 와요. 사과 · 감사 인사에 잘 어울려요.\n  · 늦어서 미안해요.\n② -(으)니까: 말하는 사람이 내세우는 까닭. 뒤에 명령 · 권유가 와도 돼요.\n  · 비가 오니까 우산을 가져가세요.\n\nBoth give a reason. -아서/어서 is a natural cause and can't take a command after it — perfect for apologies and thanks. -(으)니까 is the speaker's own reason, so a command or suggestion can follow.\n\n치즈감자 「문법」에서 두 표현을 블록 맞추기 · 바꿔 쓰기로 연습할 수 있어요.",
    "ref": "-아서/어서 · -(으)니까",
    "note": ""
  }
]
```

- `board`: 위 다섯 가지 중 하나(영어 소문자 그대로).
- `title`: **4~120자.** 학습자가 쓴 것처럼 — 30개 중 **절반은 영어, 절반은 쉬운 한국어**로(섞어도 된다).
- `body`: **3,000자 안쪽**, 보통 1~4문장. 학습자 말투(틀린 한국어가 조금 섞여도 자연스럽다 — 「이거 맞아요?」).
- `answer`: **운영자(치즈감자)의 답.** 한국어 먼저, 그다음 영어로 같은 내용. **300~1,200자**, 예문 2~4개, 6,000자를 넘지 않는다.
  줄 바꿈은 `\n`. 굵은 글씨 · 링크 · HTML 은 못 쓴다(화면이 글자 그대로 보여 준다). 끝에 사이트 어디서 더 볼 수 있는지 한 줄(「치즈감자 「문법」에서 …」)은 좋다.
- `ref`: 그 질문과 이어지는 문법 이름 · 낱말(사이트 `sentences.js` 의 `name`, 낱말 사전의 표제어). 없으면 `""`.
- `note`: 운영자가 확인해야 할 것이 있으면 적는다. 없으면 `""`.

## 반드시 지킬 것

- **다른 파일을 고치지 않는다** — 새 파일 `docs/qa-seeds.json` 하나만. 자국 · 화면 · 도구 · 표(SQL) 모두 건드리지 않는다.
- **답이 틀리면 안 된다.** 문법 설명은 널리 받아들여진 것만. 확실하지 않으면 그 질문을 빼고 다른 질문으로 바꾼다.
  예문은 맞춤법 · 띄어쓰기 · 받침 · 불규칙(들어요 · 도와요 · 몰라요)까지 맞춘다.
- **사실을 지어내지 않는다** — 기관 이름 · 전화번호 · 법 · 제도 · 요금 · 시험 날짜 · 점수 기준 · 합격 점수 같은 것은 **쓰지 않는다**.
  `life` 게시판은 「말」(부르는 법 · 호칭 · 말투)만 다룬다. `topik` 게시판은 「공부하는 법」만 — 시험 제도 · 일정 · 수수료는 쓰지 않는다.
- **실제 TOPIK 기출 문항을 옮기지 않는다.** 예로 문제를 보여 줄 때는 새로 지어 쓴다.
- 사람 이름 · 상표 · 실제 가게 · 다른 사이트 · 다른 교재 이름을 넣지 않는다. 다른 사이트 · 교재 문장을 옮기지 않는다.
- 답의 말투: 친절하고 짧게, 「~해요」체. 「좋은 질문이에요!」 같은 군말은 한 번 넘지 않게.
- 30개가 서로 겹치지 않게(같은 문법 짝을 두 번 묻지 않는다).
- 한자를 쓰지 않는다. **파일은 UTF-8, LF**(CRLF 로 저장하지 않는다).
