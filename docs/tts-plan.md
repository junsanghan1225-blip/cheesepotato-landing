# 선생님 목소리로 소리 굽기 — ElevenLabs

## 한 줄 요약

**목소리 두 벌을 만들고, 한 달 $11 로 이 판의 소리를 전부 굽고, 구독을
끊는다.** 38,791자이고 Creator 요금제 한 달치(100,000자)의 39% 다.
파일은 영원히 남는다. (`node tools/tts-manifest.mjs --count` 로 언제든
지금 값을 다시 뽑을 수 있다 — 자료가 늘면 이 수도 늘어난다.)

---

## 왜 실시간이 아니라 미리 굽는가

읽을 글이 **정해져 있고 더 안 늘어난다.** 학습자가 입력하는 글이 아니라
커리큘럼 파일에 적힌 글이다. 그래서 실시간 API 가 필요 없다.

- **돈** — 한 번 굽고 끝. 실시간이면 학생 1,000명이 하루 50번씩만 눌러도
  하루에 그보다 많은 글자가 나간다.
- **속도** — 글자 카드를 눌러 소리를 듣는 자리다. 매번 1~3초를 기다리면
  그 기능은 안 쓰이게 된다.
- **검수** — 905개를 사람이 다 들어 볼 수 있다. 이상한 것은 직접 녹음해
  바꾸면 된다. 실시간이면 틀린 발음이 검수 없이 학습자에게 나간다.
- **안전** — 입력 칸이 없으니 아무나 선생님 목소리로 아무 말이나 만들
  수 없다. 「한국어만 넣게」가 저절로 지켜진다.

---

## 목소리는 **두 벌**이 필요하다

| | 무엇 | 어디에 |
|---|---|---|
| `ELEVEN_VOICE_M` | 선생님 목소리 | 낭독 전부, 대화의 A·남자 |
| `ELEVEN_VOICE_W` | 여자 목소리 | 대화의 B·여자 |

**한 목소리로는 안 된다.** TOPIK 듣기 문항의 절반이 「여자는 무엇을
합니까」다. 둘이 같은 소리로 나오면 그 문제는 풀 방법이 아예 없다.
예문 게시판의 대화 290개도 마찬가지다 — A·B 가 같은 소리면 대화가 아니라
혼잣말로 들린다.

여자 목소리는 ElevenLabs 의 기본 한국어 목소리나 Voice Design 으로 만든
것을 쓰면 된다. 추가 비용은 없다.

---

## 무엇을 얼마나 굽는가

| 갈래 | 개수 | 글자 | 목소리 |
|---|---:|---:|---|
| `course` 코스 소리 · 글자 카드 · 빈칸 채우기 문장 | 209 | 2,672 | 하나 |
| `example` 예문 | 289 | 4,464 | 하나 |
| `dialogue` 예문 게시판 대화 | 290 | 11,702 | **둘, 이어 붙임** |
| `listen` TOPIK 듣기 대본 | 45 | 4,501 | **둘, 이어 붙임** |
| `reading` 읽기 지문 | 54 | 12,211 | 하나 |
| `writing` 쓰기 지문 | 26 | 3,241 | 하나 |
| **합계** | **913** | **38,791** | |

듣기 문항은 여든 개가 목표다(TOPIK I·II 청사진 자리를 한 벌씩 다
채우는 값). 다 채우면 7,000자쯤 더 늘어난다. 그래도 한도 안이다.

**먼저 구울 순서** — 값어치가 높은 순으로.

1. `course` — 한글을 처음 배우는 사람이 **가장 먼저 듣는 소리**다. 2,672자.
2. `listen` — 소리가 없으면 갈래 자체가 성립하지 않는다. 4,501자.
3. `example` — 4,464자.
4. `dialogue` — 11,702자.
5. `reading` · `writing` — 글자가 가장 많고 없어도 갈래는 돈다. 예산이
   빠듯하면 여기를 다음 달로 미룬다.

## 하는 법

```bash
export ELEVEN_API_KEY=...
export ELEVEN_VOICE_M=...     # 선생님 목소리 id
export ELEVEN_VOICE_W=...     # 여자 목소리 id

# 1. 무엇을 구울지 뽑는다
node tools/tts-manifest.mjs > /tmp/tts.jsonl

# 2. 얼마나 드는지 먼저 본다 (아무것도 안 굽는다)
node tools/tts-build.mjs --in /tmp/tts.jsonl --dry

# 3. 값어치 높은 것부터
node tools/tts-manifest.mjs --only course,listen > /tmp/tts1.jsonl
node tools/tts-build.mjs --in /tmp/tts1.jsonl

# 4. 듣고 괜찮으면 나머지
node tools/tts-manifest.mjs > /tmp/tts.jsonl
node tools/tts-build.mjs --in /tmp/tts.jsonl

# 5. 자국을 새로 찍고 올린다
node tools/stamp.mjs
git add assets/audio && git commit && git push
```

`ffmpeg` 가 있어야 대화를 이어 붙인다. 없으면 조각만 구워 두고 나중에
다시 돌리면 **굽지 않고 합치기만** 한다.

### 안전장치

- **이미 있는 파일은 건너뛴다.** 중간에 끊겨도 다시 돌리면 이어서 굽고,
  두 번 돌려도 돈이 두 번 안 나간다. 다시 굽고 싶으면 그 파일을 지운다.
- **굽기 전에 얼마인지 보여 주고 물어본다.** `--yes` 로 건너뛸 수 있다.
- **크레딧이 떨어지면 거기서 멈춘다.** 계속 돌려 봐야 다 실패하고 로그만
  더러워진다. 구운 것은 남으니 충전한 뒤 다시 돌리면 이어 간다.

## 이 도구가 하는 세 가지 (그냥 API 를 부르는 것과 다른 점)

**`previous_text` · `next_text`** — 대화를 한 줄씩 따로 구우면 줄마다
문장이 처음인 것처럼 읽혀서 억양이 뚝뚝 끊긴다. 앞뒤 줄을 같이 넘기면
이어지는 말투로 읽는다. 붙여 놓았을 때 차이가 크다.

**`seed`** — 파일 이름에서 씨앗을 만든다. 같은 문항은 늘 같은 씨앗을
받으므로, 문항 하나를 고쳐 다시 구워도 그것만 목소리 톤이 달라지지
않는다.

**화자 사이 0.35초** — 붙여만 놓으면 두 사람이 말을 자르고 들어오는
것처럼 들린다.

## 값을 더 뽑는 법

**모델을 갈래마다 다르게.** `--model eleven_flash_v2_5` 는 글자당 크레딧이
절반이다. 낱말 카드처럼 짧고 많은 것은 flash 로, 듣기 대본·읽기 지문처럼
억양이 중요한 것은 `eleven_multilingual_v2` 로.

**낱말 사전 5,000개** — 아직 목록에 안 넣었다. 낱말 하나가 평균 3자면
15,000자이고, flash 로 구우면 7,500자어치다. 한도 안에 들어간다. 뜻만
읽는 것보다 소리를 같이 듣는 편이 훨씬 오래 남는다.

**느린 판** — 초급 학습자용으로 같은 글을 느리게 한 벌 더 굽는 것.
글자가 두 배로 드니 `course` 처럼 짧고 중요한 것만.

## 굽고 나서 반드시 할 것

**905개를 전부 들어 본다.** 3초씩이면 한 시간이 안 된다. 미리 굽는
방식의 가장 큰 이점이 이것이다.

특히 볼 곳:

- **글자 카드(ㄱ ㄴ ㅏ …)** — TTS 가 가장 못하는 자리다. 「ㅁ」을 「미음」
  이라 읽거나 뭉갤 수 있다. 그런데 한글을 처음 배우는 사람이 가장 먼저
  듣는 소리다. **이상하면 직접 녹음해서 바꿔라.** 39개면 10분이다.
- **숫자** — 한국어 TTS 가 가장 자주 틀린다. 「2시」를 「이시」로,
  「하나」를 「일」로.
- **듣기 대본** — 남녀가 실제로 갈려 들리는지. 안 갈리면 그 문항은 못
  푼다.

## 지난 일 — 낱자 39개가 통째로 사라질 뻔했다

`audioSlug` 가 한글 음절(U+AC00~D7AF)만 남기고 있었다. ㄱ·ㅏ 같은 낱자는
호환 자모(U+3130~318F)에 있어서 통째로 지워졌고, 이름이 빈 문자열이 되어
`say('ㄱ')` 이 `assets/audio/.mp3` 를 찾고 있었다.

**녹음을 올려도 화면이 영영 못 찾는 상태였다.** 그것도 하필 한글을 처음
배우는 사람이 가장 먼저 듣는 39개가. 고쳤고(`tools/tts-manifest.mjs` 에
같은 함수가 있으니 한쪽을 고치면 다른 쪽도 고쳐야 한다), 목록의 코스
소리가 134개에서 151개로 늘었다.

## 지난 일 — 빈칸 채우기(cloze) 문장 72개가 이 목록에 없었다

`courses*.js` 의 `t:'cloze'` 블록(빈칸 채우기 문제) 76개는 화면에서 실제로
소리가 난다 — `sentence` 의 `[빈칸]` 을 채운 문장을, `audio` 필드가 있으면
그 파일을, 없으면 `audioSlug(그 문장)+.mp3` 를 찾아 재생한다
(`app.module.js` 의 `fullSay`). 그런데 `tts-manifest.mjs` 는 `say:` 와
`ch:` 필드만 훑고 있어서 `sentence`/`cloze` 는 아예 몰랐다.

**손으로 `audio` 필드를 넣어 둔 4개만 목록 밖에서 따로 살아 있었고
(그나마 `assets/audio/` 에 0바이트 자리표시자만 있었다), 나머지 72개는
구우려고 목록을 뽑아도 안 잡혀서 영영 로봇 목소리(Web Speech)로 남을
뻔했다.** 화면이 조용히 그쪽으로 넘어가므로(README.md 의 안전한 설계대로)
아무도 알아채지 못했을 것이다.

`tts-manifest.mjs` 의 `course` 절에 cloze 블록을 훑는 코드를 더했다 —
`sentence` 를 같은 규칙(`[X]` → `X`)으로 채우고, `audio` 필드가 있으면
그대로, 없으면 `audioSlug` 로 파일명을 만든다. `course` 가 151개 →
209개로 늘었다. `assets/audio/00-README.txt` 가 CP949 로 저장돼 있어
그것도 UTF-8 로 다시 썼다(이 저장소의 다른 모든 파일과 맞춘다).
