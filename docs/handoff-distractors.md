## 0. 한 줄

**보기(options)가 어색하다.** 뜻을 읽고 고르는 게 아니라, 생김새가 이상한 걸
찾거나 자리를 외워서 맞히게 돼 있다. 그걸 고치는 일이다.

빈칸 자체가 깨진 문제도 4개 있다 (§5). 그건 버그라 먼저 고쳐야 한다.

## 2. 데이터 스키마 — 정확히

### `cloze` 블록 (빈칸)

```js
{ t:'cloze',
  sentence:'오늘 저녁에는 피자를 [먹고 싶어요].',  // 대괄호 안이 빈칸이 된다
  answer:'먹고 싶어요',                          // 문자열. 대괄호와 같아야 한다
  meaning:'I feel like eating pizza tonight.',   // 회색 뜻풀이 줄 (선택)
  options:['먹을 거예요','먹으려고 해요','먹고 싶어요','먹기로 했어요'],
  keys:['먹고 싶어요','먹을 거예요','먹으려고 해요','먹기로 했어요'],
  why:'…맞힌 뒤 나오는 설명…' }
```

- `sentence` 의 **대괄호는 정확히 한 쌍**이어야 한다. 렌더러 정규식이
  `/^(.*)\[([^\]]+)\](.*)$/s` 라 욕심쟁이(greedy)여서, 두 쌍이면 **마지막
  것만** 빈칸이 되고 앞의 것은 대괄호째 화면에 남는다.
- `answer` 는 대괄호 안 글자와 **같아야 한다.** 다르면 빈칸은 대괄호 자리에
  뚫리는데 정답은 딴 것이 된다 (§5 에 실제 사례).
- 채점은 **글자 비교** (`picked === answer`) 다. 인덱스가 아니다.
- `options` 에 정답이 반드시 들어 있어야 한다. 2개 이상.
- `keys` 는 한글 자판 없는 사람용 키패드. 있으면 정답이 들어 있어야 한다.

### `choice` 블록 (고르기)

```js
{ t:'choice', q:'질문',
  options:['가','나','다'],
  answer:1,        // ← 인덱스다. cloze 와 다르다!
  why:'…' }
```

### 그 밖의 문제 종류

`type`(직접 쓰기 · `answer` 는 문자열, `keys` 선택) · `order`(`tokens`+`answer`
배열, 조각이 같아야 함) · `pair`(`pairs` 짝 배열) · `listen`(`say` 필요) ·
`speak`(`say` 필요).

## 3. 절대 어기면 안 되는 것

1. **`lesson.id` 를 바꾸지 마라.** 진도(`lesson_progress`)가 이 문자열
   하나로만 기록된다. 바꾸면 그 레슨을 끝낸 사람의 기록이 어디에도 안 붙는
   고아가 되고 되돌릴 방법이 없다. 검사기가 막는다 — 정말 버릴 때만
   `tools/check-courses.mjs` 의 `RETIRED` 에 이유와 함께 적는다.
   `blocks` 안을 고치는 건 자유다.

2. **보기 순서를 손으로 섞지 마라.** 2026-08-07 부터 **렌더러가 그릴 때
   섞는다** (`shuffled()`, 피셔–예이츠). 데이터에서 또 섞을 필요가 없고,
   `choice` 의 `answer` 인덱스는 원본 배열 기준으로 그대로 두면 된다.

3. **`index.html` 의 CSS 미디어쿼리는 스타일시트 맨 아래에 둔다.** 위에 두면
   뒤에 오는 기본값에 조용히 덮인다.

4. **색을 인라인 `style` 로 박지 마라.** 스타일시트로 못 고치게 된다.
   `--surface` `--ink` `--orange` `--green` `--line` `--tint` 등 CSS 변수만 쓴다.

5. 고친 뒤 **`node tools/check-courses.mjs` 가 통과해야 한다.**

## 4. 지금 무엇이 어색한가 — 진단 셋

### (가) 맨몸 어미를 고르게 한다

```
im-03-02-01   정답 잖아   ← 다니 / 네요 / 군요
ad-01-01-01   정답 는     ← 던 / ㄹ / 나
ad-02-01-01   정답 습니다  ← 어요 / 다 / 소
```

아무도 머릿속에서 `ㄹ` 과 `나` 를 나란히 놓고 고르지 않는다. 실제로 말할 때
고르는 단위는 **어미가 붙은 완성된 말**이다. `만날 / 만나는 / 만났던 / 만난`
처럼 되어야 뜻을 견줄 수 있다. 같은 레슨의 `blocks[3]`,`blocks[4]` 는 이미
그렇게 돼 있으니, `blocks[1]`,`blocks[2]` 만 결이 다르다.

### (나) 한 레슨 안에서 크기가 들쭉날쭉하다

`im-02-03-01` 은 `오는 바람에`(구) 와 `바람에`(어미) 가 섞여 있다. 같은
레슨인데 어떤 문제는 구를 고르고 어떤 문제는 어미를 고른다. 학습자는
매번 "이번엔 어디까지 고르는 거지" 를 다시 판단해야 한다.

### (다) 지어낸 말 — 이건 이미 손봤다

`먹으 싶어요` · `읽ㄹ 거예요` · `갸요` · `만낫요` 처럼 **없는 말**을 보기에
넣어 뒀었다. 그러면 뜻을 안 보고 생김새만 보고 고르게 된다. 문법 공부가
아니라 오타 찾기다.

`bg-d-01` · `bg-d-02` 는 2026-08-07 에 고쳤다. `im-*` · `ad-*` 는 원래부터
실재하는 말을 쓰고 있어서 이 문제는 없다 — (가)(나)만 남았다.

## 5. 먼저 고쳐야 할 버그 — 빈칸 4개가 깨져 있다

```
im-03-02-01 blocks[1]
  원본 : A: 저 다음 달에 결혼해요! B: 결혼하신다니! [너무 놀라워요]
  화면 : A: 저 다음 달에 결혼해요! B: 결혼하신다니! ____
  정답 : 다니
  → 대괄호가 "너무 놀라워요" 를 감싸는데 정답은 "다니". 빈칸이 엉뚱한 데 뚫린다.

ad-02-01-01 blocks[1]
  원본 : [사내 회의록] 금일 제 3차 정기 이사회는 서면으로 진행되었[습니다].
  → 대괄호 2개. "[사내 회의록]" 이 화면에 대괄호째 남는다.

ad-02-01-01 blocks[2]
  원본 : [단톡방] A: 야 술 한잔 할[래]? B: 좋아! 저녁 7시에 봐!
  → 같은 문제.

ad-02-01-01 blocks[4]
  원본 : [사극 드라마 임금님 말씀] 감히 신하가 이런 말을 하[시오]? 용서가 안 되[오].
  화면 : [사극 …말씀] 감히 신하가 이런 말을 하[시오]? 용서가 안 되____.
  정답 : 시오
  → 대괄호 3개. 마지막([오])에 빈칸이 뚫리는데 정답은 "시오". 앞의 [시오] 는
    답이 화면에 그대로 노출된다.
```

**고치는 법** — 상황 설명은 대괄호 말고 `meaning` 이나 `q` 로 빼거나 괄호 `()`
를 쓴다. 빈칸 대괄호는 문장에 한 쌍만 남긴다.

## 6. 좋은 선지의 기준

말로 옮기면 이렇다.

1. **넷 다 실제로 쓰는 말이어야 한다.** 지어내지 않는다.
2. **넷 다 그 문장에 문법적으로는 들어갈 수 있어야 한다.** 갈리는 것은 **뜻**
   이다. 그래야 문맥을 읽는다.
3. **크기를 맞춘다.** 완성된 말끼리 견준다. 맨몸 어미와 구를 섞지 않는다.
4. **`why` 는 나머지 셋이 각각 무슨 뜻인지 말해 준다.** 틀린 보기를 고른
   순간이 제일 잘 배우는 자리인데, "틀렸다" 만 하고 넘어가면 그 자리를 버린다.

좋은 예 (2026-08-07 에 이렇게 바꿨다):

```js
{ t:'cloze', sentence:'나중에 세계 여행을 [가고 싶어요].', answer:'가고 싶어요',
  meaning:'I want to travel the world someday.',
  options:['갈 거예요','가고 싶어요','가려고 해요','가기로 했어요'],
  keys:['가고 싶어요','갈 거예요','가려고 해요','가기로 했어요'],
  why:'넷 다 쓰는 말입니다. **갈 거예요** 는 일정이 잡혔다, **가려고 해요** 는 마음을 먹었다, **가기로 했어요** 는 정해서 약속했다는 뜻이에요. “나중에” 는 아무것도 안 정한 상태라 바람 쪽입니다.' }
```

`why` 안에서 `**굵게**` 와 `` `코드` `` 가 먹는다.

## 7. 곁들여 — 고르기만 시키지 않기

같은 날 받은 지적이다. 보기에서 고르기만 하면 읽을 줄만 알게 된다.
`bg-d-02` 에는 **직접 쓰기 2 · 짝 맞추기 2 · 배열 1** 을 섞어 뒀으니 그 결을
따라가면 된다. 규칙(받침 유무 같은 것)은 특히 고르기로 안 익어서 `type`
블록으로 직접 쓰게 해야 한다.

레슨 구조도 참고할 것 — `bg-d-02` 는 **뜻 → 만드는 법 2단계 → 표 → 예문 →
함정 → 문제** 순서다. `im-*` · `ad-*` 8개 레슨은 아직 `text` 하나에 cloze 몇
개뿐이라 같은 틀로 넓히면 좋다.

예문은 `{ t:'chars', wide:true, items:[{ch:'문장', tip:'뜻'}] }` 로 넣는다.
`wide` 를 빼면 낱글자용 큰 카드라 문장이 넘친다. 누르면 읽어 준다.
