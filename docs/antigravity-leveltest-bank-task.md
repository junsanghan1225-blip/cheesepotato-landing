# 안티 그래비티 작업 지시 — 레벨테스트 문제 은행 30문제씩 + 문법 꼬리표

> 이 파일과 `AGENTS.md` 를 같이 붙여 넣는다. 첫 줄: 「AGENTS.md 를 먼저 읽고, 이 지시문대로만 해.」 (운영자 결정 2026-10-05)

## 왜

레벨테스트는 이제 **계단식**이다. 맞히면 한 칸 위, 틀리면 한 칸 아래 문제가 나온다.
분석 테스트는 영역마다 **레벨 확정**(그 레벨 2문제 이상 맞힘 + 다음 레벨 2문제 이상 틀림)까지 묻는다.

지금 문제 수는 이렇다.
- 문법(`leveltest-overall.js`): 레벨마다 20문제
- 쓰기(`leveltest-writing.js`): 레벨마다 **8문제**

이대로면 다시 볼 때 같은 문제를 만난다. **레벨마다 30문제**로 채운다.

결과지의 「다시 볼 것」은 틀린 문제를 **그 문법 쪽으로 잇는다.** 그래서 모든 문제에 **문법 꼬리표 `g`** 를 단다.

## 할 일 — 셋

1. `leveltest-overall.js`(문법 영역): **L0 ~ L7 각 10문제 더** → 레벨마다 30. 모두 80문제.
2. `leveltest-writing.js`(쓰기 영역): **L2 ~ L7 각 22문제 더** → 레벨마다 30. 모두 132문제.
3. **두 파일의 모든 문제(있던 것 + 새것)에 `g` 를 단다.**
   - `g` = 그 문제가 묻는 문법의 「예문 만들기」 표현 id(문자열, 예: `"26-3"`).
   - 표현 목록은 `sentences.js` · `sentences-beginner.js` · `sentences-intermediate.js` 의 `SB_CATS[].points[]` 에 있다(`id` · `name`).
   - L0(한글 읽기)처럼 문법을 묻지 않는 문제는 `g` 를 달지 않는다.
   - 꼭 맞는 표현이 없으면 달지 않는다. 비슷한 것으로 억지로 달지 않는다.

```js
{ lv: 4, g: '32-1', q: '배가 ___ 병원에 갔어요.', options: ['아파서', '아프고', '아프면', '아프지만'], answer: 0, why: '이유를 말할 때는 「-아/어서」를 써요.' }
```

## 레벨 — 파일의 주석 칸 그대로

| 레벨 | 무엇 |
|---|---|
| L0 | 한글 읽기(로마자 표기) — 문법 영역만 |
| L1 | 입문: 이에요/예요 · 은/는 · 인사말 · 기본 단어 — 문법 영역만 |
| L2 | 초급 1: 조사 을/를 · 이/가 · 에 · 에서 · 에게, 안/못, -아요/어요 |
| L3 | 초급 2: 과거 -았/었-, -고 있다, -기 전에 · -(으)ㄴ 후에, 불규칙 |
| L4 | 초급 3: -아서/-(으)니까, -(으)면, -는데, -고 싶다, -아/어 주다, -아야 하다 |
| L5 | 초급 4: -아/어 본 적이 있다, -(으)러, -(으)ㄹ 것 같다, 관형형, 높임말 |
| L6 | 중급(TOPIK 3 · 4급): -느라고, -는 바람에, -(으)ㄹ 텐데, -다가, -도록, -더라고요, -아/어 놓다 … |
| L7 | 고급(TOPIK 5 · 6급): -(으)ㄹ수록, -기는커녕, -는 한, -(으)ㅁ에도 불구하고, 문어체 연결 … |

- 한 레벨 안에서 **문법을 고루** 나눈다. 같은 문법만 되풀이하지 않는다.
- 이미 있는 문제와 **같은 문장을 낱말만 바꿔** 다시 쓰지 않는다.

## 지킬 것

- 모양은 파일 맨 위 설명과 똑같이 쓴다: `lv` · `g` · `q` · `options`(꼭 4개) · `answer`(0~3) · `why`(꼭).
  - 쓰기 영역은 빈칸 `___` 이 있는 문장이다.
- **정답은 하나뿐.** 오답 보기는 문장에 넣으면 **확실히 틀린 말**이어야 한다.
  - 같은 뜻의 다른 문법(「-아서」 자리에 「-니까」가 될 수 있는 문장 등)은 오답으로 쓰지 않는다.
- 정답 자리(`answer`)를 0~3 에 고루 나눈다. 늘 0번에 두지 않는다.
- `why` 는 해요체 한두 문장으로, 왜 그 답인지 쓴다.
- 사실을 지어내지 않는다: 통계 · 기관 · 실존 인물 · 연예인 · 브랜드 · 가게 이름을 쓰지 않는다. 이름은 「민수 · 지영 · 수진」처럼 흔한 것만.
- 숫자 · 시간은 한글로 써도 되고 숫자로 써도 된다. 다만 한 문제 안에서는 한 가지로.
- 각 레벨 주석 칸 아래, 그 레벨 마지막 문제 뒤에 더한다(순서 유지).

## 내는 법

```bash
git fetch origin && git checkout -b leveltest-bank origin/main
# 두 파일에 문제를 더하고, 모든 문제에 g 를 단다
node tools/check-leveltest.mjs      # 「이상 없음」 + 레벨마다 30 + 「문법 꼬리표 없음」이 L0 문제 수(30)쯤만 남아야 한다
git add leveltest-overall.js leveltest-writing.js && git commit -m "leveltest: 30 per level + grammar tags"
git push -u origin leveltest-bank
```

- **다른 파일 · 도구(`tools/`)는 고치지 않는다.** 자국(stamp)도 찍지 않는다. PR 은 열지 않는다.
- 한 번에 다 못 하면 ① 꼬리표 → ② 쓰기 → ③ 문법 순서로 나눠 커밋해도 된다. 커밋마다 검사를 통과해야 한다.
- 자신 없는 문제는 `// 운영자 확인 — 이유` 주석을 그 문제 위에 단다(Claude 가 검토한다).

## Claude 가 검토할 것 (안티는 참고만)

- 정답이 하나뿐인지, 오답이 확실히 틀렸는지, 레벨이 맞는지
- `g` 가 그 문제의 문법과 맞는지
- 한국어가 자연스러운지, 지어낸 사실이 없는지
