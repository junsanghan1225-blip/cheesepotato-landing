# 커뮤니티 — 위에서부터 짜기 (초안, 2026-10-01)

> 운영자 요청: 한국어 지식을 나누는 커뮤니티. Reddit 처럼 쓰거나, 네이버 지식iN 처럼 질문과 답만 오가게.
> 학생이 질문하면 운영자가 답하거나 학생끼리 답한다. 이 문서는 **제안**이다. 만들기 전에 아래 7의 결정이 필요하다.

## 0. 한 줄 요약 — 추천

**「질문이 중심인 Reddit」**. 첫 화면과 글쓰기는 지식iN 처럼 **질문 → 답 → 채택**으로 단순하게 두고,
Reddit 의 힘인 **추천(업보트) · 주제별 게시판 · 댓글 스레드 · 꼬리표(flair) · 명성(카르마)** 을 얹는다.

왜: 지금 우리 사람들은 「궁금한 게 생긴 학습자」다. 빈 자유 게시판은 아무도 먼저 안 쓰지만(자료마당이 그랬다),
질문은 저절로 생긴다. 한편 답이 쌓이면 **검색에 걸리는 한국어 Q&A 모음**이 되어 사이트로 사람을 데려온다 — 이건 Reddit 방식이 강하다.

## 1. 두 모델 비교

| | Reddit | 지식iN | 우리(추천) |
|---|---|---|---|
| 글의 모양 | 아무 글(질문 · 팁 · 자랑 · 밈) | 질문만 | **질문 중심** + 「팁 · 자료」 꼬리표만 따로 허용 |
| 좋은 답 가리기 | 추천 수로 위로 | 질문자가 **채택** | 둘 다: 채택 답은 맨 위 고정, 나머지는 추천순 |
| 모임 | 주제별 서브레딧 | 분류 | 주제 게시판 몇 개(아래 3) — 처음엔 적게 |
| 명성 | 카르마 | 등급 · 내공 | 명성 점수 + 배지(치즈 · 감자 레벨과 이어 붙일 수 있다) |
| 운영 | 모더레이터 | 회사 | 운영자 + 나중에 믿을 만한 학생 몇 명 |
| 빈 화면 걱정 | 크다 | 작다 | 작다 — 질문은 늘 생긴다 |

## 2. 누가 · 왜 오나

- **질문하는 학습자** — 「-아서 와 -니까 차이?」 「이 문장 자연스러워요?」 — 빠르고 믿을 만한 답을 원한다.
- **답하는 사람** — 운영자(처음엔 거의 모든 답), 고급 학습자, 한국인. 인정(추천 · 채택 · 배지)을 원한다.
- **검색으로 들어온 사람** — 같은 질문의 답을 읽고 간다. 이 사람이 사이트를 알게 되는 입구.

## 3. 게시판(처음엔 다섯)

문법 · 낱말과 표현 · TOPIK · 발음과 말하기 · 한국 생활(EPS 포함). 더 나누는 것은 글이 쌓인 뒤에.

## 4. 기능 — 층별 (위에서부터)

**1층 — 꼭 있어야 여는 것 (MVP)**
1. 질문 쓰기(제목 · 본문 · 게시판 · 꼬리표) — 로그인한 사람만. 읽기는 누구나.
2. 답 쓰기 · 답에 댓글(한 단계만 — 깊은 스레드는 2층)
3. 추천(▲)과 정렬(인기 · 새 글 · 답 없는 글)
4. **채택** — 질문자가 답 하나를 고른다. 채택되면 질문에 「해결」 표시
5. 신고 · 숨김(운영자), 내 글 지우기, 글자 수 · 하루 글 수 한도(도배 막기)
6. 검색(제목 · 본문)
7. 글마다 주소(`/community/…`) — 검색에 걸리게. 운영자 답 · 채택 답이 있는 글만 검색 엔진에 연다(빈 글이 걸리면 사이트 인상이 나빠진다)

**2층 — 커지면**
- 명성 점수 · 배지(추천 받음 · 채택 받음), 프로필 쪽(내 질문 · 내 답)
- 알림(내 질문에 답이 달림 · 채택됨) — 처음엔 사이트 안 알림만, 메일은 나중에
- 댓글 스레드(여러 단계), 글 고치기 기록
- **우리 자료와 이어 붙이기**: 글에 문법 표현 · 낱말을 적으면 그 쪽으로 가는 카드가 뜬다(「-아서」 → 문법 쪽). 거꾸로 문법 쪽 아래에 「이 표현에 대한 질문」

**3층 — 나중에**
- 믿을 만한 학생을 모더레이터로, 「원어민 확인」 배지
- Pro 혜택(예: 운영자 답 먼저 받기) — 결제를 켠 뒤에 정한다
- AI 도움 — 질문을 쓰면 비슷한 질문 · 문법 쪽을 먼저 보여 준다(중복 질문 줄이기)

## 5. 운영 · 안전 — 여는 날부터

- 신고 → 운영자 확인 → 숨김. 자료실의 신고 기능(`resource_reports`)과 같은 틀을 쓴다.
- 금지: 광고 · 개인정보(전화번호 · 주소) · 욕설 · 시험 문제 유출(실제 TOPIK 문항 올리기 — 저작권), 대리 작성 의뢰.
- 이용 약관 · 개인정보 처리 방침에 커뮤니티 조항을 더해야 한다(글의 권리 · 지우는 기준 · 보관 기간).
  **어떤 조항이 법으로 꼭 필요한지는 운영자가 확인한다** — 지어내지 않는다.
- 미성년 학습자도 있다 — 쪽지(1:1 메시지)는 넣지 않는다.

## 6. 만드는 순서 · 품

| 단계 | 무엇 | 누가 |
|---|---|---|
| 1 | 결정(아래 7) | 운영자 |
| 2 | 표 설계 `db/add_community.sql` — posts · answers · votes · reports, 읽기는 누구나 · 쓰기는 로그인 · 지우기는 본인과 운영자(RLS) | Claude 가 파일로, 운영자가 SQL Editor 에서 실행 |
| 3 | 화면 1층(목록 · 글 · 쓰기 · 답 · 추천 · 채택 · 신고) | Claude |
| 4 | 씨앗 질문 20~30개 — 학습자가 실제로 자주 묻는 것으로, 운영자 답과 함께(빈 게시판 막기) | 안티 그래비티 초안 → 운영자 검토 |
| 5 | 검색에 걸리는 글 쪽(정적 쪽 또는 Edge Function) | Claude — 방법은 3단계 뒤에 정한다 |
| 6 | 2층 | 글이 쌓인 뒤 |

## 6.5 운영자 결정 (2026-10-01)

- 모델: **지식iN 처럼**(질문 → 답 → 채택). 답은 **처음엔 운영자만**(「일단 나부터」).
- ✅ 1층 일부를 만들었다 — 표 `db/add_community.sql`(운영자가 SQL Editor 에서 실행), 화면 「묻고 답하기」(#learn/qna):
  질문 목록(갈래 · 찾기 · 새 질문/답 기다림) · 질문 쪽 · 질문하기(로그인, 하루 5개) · 답(운영자) · 채택 · 도움돼요 · 신고 · 지우기 · 숨기기(운영자).
  표가 없으면 「곧 열려요」.
- 아직: 검색에 걸리는 글 쪽(5단계), 씨앗 질문(4단계), 알림 · 명성(2층).
