# 한국어 도우미 사이드바 — 설계

작성 2026-08-27. 아직 코드는 없다. 무엇을 만들지와 **어디까지 AI에 맡길지**를 정한다.

---

## 0. 결론부터

**이건 챗봇이 아니다. 조회기에 AI를 얹은 것이다.**

한국어 학습 사이트에서 사람이 옆칸에 치는 말의 대부분은 이런 것이다.

```
가지고        ← 낱말 뜻
-느니         ← 문법 이름
-느니랑 -을 바에야 차이가 뭐예요?   ← 이건 진짜 질문이다
```

앞의 둘은 **질문이 아니라 조회다.** 우리한테 이미 답이 있다. 그걸 AI에
물으면 느리고, 비싸고, 가끔 틀린다. 셋째만 AI가 필요하다.

그래서 층을 나눈다. 0층이 규칙으로 답하고, 1층이 AI다.

---

## 1. 왜 이 자리가 특별한가 — 자료가 이미 브라우저에 있다

보통 이런 걸 만들면 벡터 DB를 세우고, 임베딩을 만들고, 서버에 색인을
얹는다. **우리는 하나도 필요 없다.** 방문자가 이미 자료를 통째로 받아
가지고 있기 때문이다.

| 파일 | 무엇 | 크기 |
|---|---|---|
| `glossary.js` | 낱말 4,737개 (국립국어원 뜻풀이) | 245 KB |
| `sentences*.js` | 표현 290개 — 뜻풀이·형태·주의할 점·예문·대화문 | 250 KB |
| `grammar.js` | 문법 항목 197개 | 32 KB |
| `reading.js` | 읽기 지문 54편 | 114 KB |

찾는 연장도 이미 있다.

- `gloss-find.js` — 「가지고」처럼 활용된 꼴을 사전의 「가지다」로 되돌린다.
- `grammar-find.js` — 글 속에서 문법 표현을 집어낸다.

즉 **검색(RAG의 R)은 브라우저에서 공짜로 끝난다.** 서버로는 찾아낸
조각 한두 줌만 올라간다. 자료 전체를 프롬프트에 밀어 넣지 않는다.

### 그리고 이 저장소에는 이미 지켜야 할 규칙이 하나 있다

`gloss-find.js` 맨 위에 이렇게 적혀 있다.

> **틀린 뜻을 내주느니 빈 칸을 내준다.**
> 떼어 낸 결과가 사전에 실제로 있을 때만 인정한다. 지어내지 않는다.

사이드바는 이 문장을 그대로 물려받는다. 아래 §5가 그것이다.

## 2. 두 층

| | 0층 · 조회 | 1층 · AI |
|---|---|---|
| 무엇이 | 규칙 + 우리 자료 | Gemini |
| 언제 | 낱말·문법·표현을 찾을 때 | 설명·비교·왜냐고 물을 때 |
| 로그인 | 필요 없다 | **필요하다** |
| 값 | 공짜 | 하루 한도 |
| 빠르기 | 즉시 | 1~3초 |
| 오프라인 | 된다 | 안 된다 |

**0층이 먼저 답하고, 못 하면 1층으로 넘긴다.** 넘길 때도 0층이 찾아낸
것을 근거로 함께 올린다 — 그게 1층의 재료다.

```
사람이 친 말
   │
   ├─ 낱말인가?      → GLOSSARY + gloss-find   ─┐
   ├─ 문법 이름인가?  → GRAMMAR + grammar-find   ├→ 0층이 바로 답한다
   └─ 표현인가?      → SB_CATS / SB_MORE       ─┘        (공짜·즉시)
   │
   └─ 그 밖의 질문 ─→ 0층이 근거를 그러모아 ──→ 1층 (Edge Function)
                                                   │
                                       근거가 없으면 → 「모르겠어요」
```

**규칙으로 되는 것을 AI에 넘기지 않는다.** 이건 취향이 아니라 비용과
일관성의 문제다 — `docs/topik-writing-plan.md` §3에 같은 말이 있다.

## 3. 화면

```
배우기 어느 화면에서든  ─  오른쪽 아래 🧀 단추
                              │
                    ┌─────────┴──────────┐
   넓은 화면 → 오른쪽 사이드바      좁은 화면 → 아래에서 올라오는 시트
```

**휴대폰이 기준이다.** 대부분이 휴대폰으로 공부한다(FAQ에 우리가 그렇게
적어 뒀다). 좁은 화면에서 사이드바는 자리가 없으므로 아래 시트로 바꾼다.
넓은 화면에서만 옆에 붙인다.

화면에 반드시 있어야 할 것:

1. **출처.** AI가 한 말 밑에 무엇을 보고 답했는지 걸어 준다 —
   `/sentence/23-1.html`, 사전의 그 낱말. 사람이 직접 확인할 수 있어야 한다.
   덤으로 안쪽 링크가 늘어 검색에도 좋다.
2. **AI가 한 말이라는 표시.** 0층 답과 1층 답은 생김새가 달라야 한다.
   사전 뜻풀이는 국립국어원이 쓴 것이고 AI 답은 아니다.
3. **남은 횟수.** 다 쓰고 나서 알면 늦다.
4. **지금 보던 것.** 레슨을 보다 열면 그 레슨을, 표현을 보다 열면 그
   표현을 사이드바가 알고 시작한다.

## 4. 서버 — `ask-korean`

지금 저장소가 쓰는 길을 그대로 늘린다. 새 함수를 하나 만든다.

```
브라우저 ──(질문 + 0층이 찾은 근거)──→ Edge Function ──→ Gemini
                                        (service_role 로 한도 확인)
```

- **이름**: `ask-korean`. `recognize-word`·`score-pronunciation`과 같은
  결이다. 기존 함수에 mode를 하나 더 붙이지 않는다 — 그 함수를 고치면
  **구버전 앱이 즉시 새 코드를 타게 된다.** 발음 채점 때 이미 정한 방침이다
  (`specs/2026-07-30-ai-pronunciation.md` 계약).
- **키**: 함수 안에만 둔다. 브라우저에서 Gemini를 직접 부르면 키가 페이지에
  드러난다.
- **인증**: `auth.getUser()`로 진짜 로그인 사용자인지 확인한다. anon 키도
  유효한 JWT라서 `verify_jwt`만으로는 부족하다 — `recognize-word`가 겪은 일이다.
- **모델**: `gemini-3.6-flash`. 이미 쓰는 것.

### 한도는 컬럼을 더한다 — 행을 늘리지 않는다

```sql
alter table public.ai_usage
  add column if not exists chat_count integer not null default 0;
```

**`kind` 컬럼을 넣어 기본키를 `(user_id, day, kind)`로 바꾸면 안 된다.**
하루에 행이 둘이 되는데 앱의 `DashboardScreen.tsx`가 `.maybeSingle()`로
읽는다. 행이 둘이면 `maybeSingle()`은 오류를 내고 `data`를 null로 준다.
그 코드는 error를 무시하고 `usage?.count ?? 0`을 쓰므로 **대시보드가 조용히
"0회"를 보여 준다.** 앱을 업데이트하지 않은 사람에게는 고장으로 보인다.
컬럼을 더하면 행은 하나라 구버전 앱이 그대로 돈다.

이건 `pron_count`를 넣을 때 이미 한 번 짚은 것이다(`db/add_pron_count.sql`).
세 번째도 같은 방식으로 간다.

| 무엇 | 컬럼 | 하루 |
|---|---|---|
| 사진으로 단어 만들기 | `count` | 30 |
| 발음 진단 | `pron_count` | 20 |
| **한국어 도우미** | **`chat_count`** | **처음엔 20** |

셋을 따로 센다. 도우미를 많이 썼다고 사진 인식이 마르면 안 된다.

**차감은 Gemini 호출이 실제로 성공한 뒤에만.** 키 누락이나 서버 오류까지
사용자에게 물리지 않는다. 앞의 두 함수와 같은 태도다.

### 오갈 것

```jsonc
// 받는 것
{
  "q": "-느니랑 -을 바에야 차이가 뭐예요?",
  "lang": "ko",                    // 화면 언어. ko | en
  "cites": [                       // 0층이 브라우저에서 찾아 올린 근거
    { "id": "1-1", "name": "-느니", "desc": "…", "more": ["…"], "ex": "…" },
    { "id": "1-2", "name": "-(으)ㄹ 바에야", "desc": "…", "more": ["…"], "ex": "…" }
  ],
  "where": "learn/sentence/1-1"     // 지금 보던 화면
}

// 주는 것
{
  "answer": "…",
  "used": ["1-1", "1-2"],          // 실제로 쓴 근거만
  "grounded": true                  // false 면 화면이 「모르겠어요」를 띄운다
}
```

## 5. 넘지 말아야 할 선

**① 근거가 없으면 답하지 않는다.**
`cites`가 비었거나 질문과 상관없으면 지어내지 말고 `grounded: false`를
돌려준다. 화면은 「이건 제가 가진 자료에 없어요」와 검색 단추를 보여 준다.
「ChatGPT 쓰세요」 소리를 들을 수는 있다. 그래도 **틀린 문법을 가르치는
것보다 낫다.** 이 사이트를 쓰는 사람은 그 말을 그대로 외운다.

**② 시험 문제를 대신 풀어 주지 않는다.**
TOPIK 문항이나 쓰기 화면에서 사이드바에 물어 답을 받으면 그건 공부가
아니라 커닝이다. `where`가 문항 화면이면 답 대신 **무엇을 보라는 힌트만**
준다. 이 선을 안 그으면 문항 362개를 공들여 만든 뜻이 없어진다.

**③ 저장하지 않는다.**
대화를 DB에 쌓지 않는다. 화면에만 있다가 새로고침하면 사라진다.
발음 진단 때와 같다(NG-3). 쌓기 시작하면 개인정보 처리방침과 데이터
세이프티를 고쳐야 하고, 사진·동영상 정책 심사를 막 통과한 지금 새 수집
항목을 더할 이유가 없다.

**④ AI가 한 말과 사전이 한 말을 섞지 않는다.**
낱말 뜻풀이는 국립국어원 것을 CC BY-SA로 쓴다. AI가 고쳐 쓴 것을 그
뜻풀이인 양 보여 주면 출처를 속이는 것이다.

## 6. 단계

| 단계 | 무엇 | AI | 로그인 |
|---|---|---|---|
| 1 | 사이드바 껍데기 + **0층 조회** (낱말·문법·표현) | 없음 | 필요 없음 |
| 2 | `ask-korean` + 근거 전용 답변 + 출처 | Gemini | 필요 |
| 3 | 보던 화면을 아는 것 (`where`) · 문항 화면 잠금 | — | — |
| 4 | (나중) 틀린 문제를 근거로 먼저 말 걸기 | — | — |

**1단계만으로도 쓸 만하다.** 지금 사전 4,737개를 실제로 꺼내 쓰는 길은
`tqGloss` **하나뿐이고, TOPIK 지문에서 낱말을 눌렀을 때만 열린다.** 코스를
보다가, 표현을 보다가 모르는 말이 나오면 찾을 데가 없다. 자유롭게 쳐서 찾는
칸이 어디에도 없다. 0층만 있어도 그 구멍이 메워진다 — **이미 받아 놓고 안
쓰던 245KB를 사이트 전역에서 쓰게 만드는 일이다.**

AI가 안 붙어도 사이드바가 죽지 않는다 — 발음 테스트가
`score-pronunciation` 없이 도는 것과 같은 구조다.

## 7. 먼저 확인해야 할 것

- **개인정보 처리방침.** 사용자가 친 글이 Gemini로 나간다. 지금까지 앱에서
  나간 것은 사진이었고 그건 이미 적혀 있다. **글도 나간다고 적어야 한다.**
  `privacy.html`은 앱 저장소의 `docs/privacy-policy.md`에서 만들어지므로
  (`tools/build-privacy.js`) 그쪽을 먼저 고친다. 2단계 배포 전에 끝나야 한다.
- **하루 20회가 맞는지.** 채팅은 한 번 묻고 마는 게 아니라 서너 번 주고받는다.
  0층이 얼마나 받아 내느냐에 따라 완전히 달라지므로 **1단계를 띄워 0층
  적중률을 재 본 뒤** 정한다.
- **`score-pronunciation`이 아직 미배포다.** 미배포 함수가 둘이 되기 전에
  순서를 정하는 편이 낫다.
- **이름.** 사이트 마스코트가 🧀🥔이고 대화문의 두 사람이 치즈와 감자다.
  도우미를 그중 하나로 부르면 결이 맞는다.
- **0층이 못 찾는 말.** `gloss-find.js`가 처음엔 열에 넷만 찾아냈다고 적혀
  있다. 사이드바는 지문이 아니라 **사람이 직접 친 말**을 받으므로 오타와
  띄어쓰기가 더 험하다. 못 찾은 말을 (저장 말고) 세어 보는 자리가 필요하다.
