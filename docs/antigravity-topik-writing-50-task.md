> 지금: **120문항 — 51번 30 · 52번 30 · 53번 30 · 54번 30**(`node tools/check-writing.mjs` → 「이상 없음」).
> 이번: 번호마다 **20개씩 더해 50개씩, 모두 200문항.**
> 53 · 54번은 **AI 채점**(`supabase/functions/grade-writing`)이 문항의 `points` · `model` · `samples` 를 그대로 채점 기준으로 쓴다 —
> 이 칸이 틀리면 학생 점수가 틀린다. **양보다 정확성.**

## 할 일 — 네 커밋

1. **꼭 새로 받은 main 에서**: `git fetch origin && git checkout -b topik-writing-50 origin/main`
2. `topik-writing.js` 의 `TW_ITEMS` 에 더한다. **같은 번호끼리 모아서**(51번 끝에 51번, 52번 끝에 52번 …), id 는 그 번호의 다음 수부터
   (`w51-31` ~ `w51-50`, `w52-31` ~ `w52-50`, `w53-31` ~ `w53-50`, `w54-31` ~ `w54-50`).
3. 모양은 **이미 있는 문항을 그대로** 따른다 — `w51-1` · `w52-1` · `w53-1` · `w54-1` 과 마지막 문항(`w5x-30`)을 먼저 읽는다.
4. 번호 하나를 다 쓰면 검사하고 커밋한다:
   ```bash
   node tools/check-writing.mjs     # 「고쳐야 할 것」 0 · 「짚어 둘 것」 0 · 「이상 없음」
   git add topik-writing.js && git commit -m "topik writing: Q51 +20 (50)"     # 52 · 53 · 54 도 같은 꼴
   ```
5. 넷 다 끝나면 `git push -u origin topik-writing-50`. PR 은 열지 않는다 — Claude 가 검토하고 연다. **push 까지 꼭 한다.**

**이번에는 `topik-writing.js` 하나만 고친다.** `index.html` · `llms.txt` 의 숫자, `node tools/build-pages.mjs`(쓰기 쪽 · 채점용 items.json),
`stamp` 는 **Claude 가 넣을 때 한다** — 안티 쪽에서 돌리지 않는다(main 이 그새 바뀌어 자국이 어긋나는 일을 막는다).

## 번호마다 반드시 있어야 하는 것

- 51번은 실용문(안내 · 초대 · 문의 · 공지 · 부탁, `register: 'formal'`), 52번은 설명문(`register: 'plain'`).
- 빈칸의 정답은 **앞뒤 문장만 보고 하나로 좁혀져야** 한다. 여러 답이 되면 `answers` 에 다 넣는다.

**54번** (`lv: 'advanced'`) — 논술 600~700자. 53번과 같은 칸에, `data` 대신 `tasks` 셋, `min: 600, max: 700`.
배점 **내용 12 · 구조 12 · 언어 26**(합 50).

## 예시 답안(samples) — 가장 중요

AI 는 이 셋을 보고 **점수의 눈높이**를 맞춘다.

| | 53번 total | 54번 total | 모습 |
|---|---|---|---|
| 상 | 26~29 | 44~49 | 과제를 다 채우고, 문단 · 연결이 자연스럽고, 문체가 한결같다. **분량을 채운다** |
| 중 | 17~22 | 28~35 | 과제는 거의 채웠지만 문단을 안 나누거나, 어휘가 단순하거나, 문체가 한두 번 섞인다 |
| 하 | 8~14 | 12~22 | 분량이 모자라거나, 과제를 빠뜨리거나, 해요체로 쓰거나, 문법 오류가 잦다 |

- 모든 예시에 `level` · `total` · `scores{content, structure, language}` · `text` · `why`.
  **`scores` 를 더하면 `total`**, 칸마다 배점을 넘지 않는다. 차례는 상 · 중 · 하, 점수는 상 > 중 > 하.
- 「중」 · 「하」는 **실제 학습자가 쓸 법한 실수**(조사 빠뜨림 · -습니다 섞임 · 같은 말 되풀이 · 과제 하나 빠뜨림)로. 일부러 엉터리로 쓰지 않는다.
- `why` 에 글자 수를 적으면(「132자로 분량 미달」) **실제 글자 수와 맞아야** 한다 — 검사기가 센다.
- `why` 는 **어느 영역에서 왜 깎였는지**를 한두 문장으로(「언어 사용에서 합니다체가 섞여 크게 깎였다」처럼).

## 주제와 내용

- **기출 문제를 옮기지 않는다.** 실제 TOPIK 에 나온 주제 · 자료 · 질문을 그대로 쓰지 않는다. 형식과 난이도만 따르고 내용은 새로 쓴다.
- **이미 있는 문항과 주제가 겹치지 않게** — 먼저 본다:
  `node -e "import('./topik-writing.js').then(m=>m.TW_ITEMS.forEach(x=>console.log(x.id, x.title)))"`
- 51번: 동아리 모집 · 물건 찾기 · 이사 인사 · 수업 바꾸기 · 행사 미루기 · 빌린 물건 돌려주기 같은 생활 글.
- 52번: 생활 속 과학 · 습관 · 언어 · 문화의 짧은 설명(「사람은 왜 … 할까」).
- 53번: 통계 · 설문(1인 가구 · 걷기 운동 · 전자책 · 일회용품 · 외국어 공부 앱 · 주말 여가 …). 수치는 **그럴듯하되 지어낸 것**,
  조사한 곳은 가상(「한국생활연구소」처럼) — **실제 기관 이름을 쓰지 않는다.** 수치끼리 앞뒤가 맞아야 한다(비율 합 · 증감폭 계산).
- 54번: 사회 · 교육 · 기술 · 환경 · 직업(독서의 힘 · 실패의 가치 · 혼자 하는 공부와 함께 하는 공부 · 광고와 소비 …).
  질문 셋은 「의미/중요성 → 문제/원인 → 해결/노력」 흐름. 한쪽 입장을 강요하는 주제(정치 · 종교)는 피한다.
- 사람 이름 · 상표 · 실제 가게 · 회사를 넣지 않는다. 한자를 쓰지 않는다.

## 하지 말 것

- `tools/` 의 도구를 고치지 않는다. 검사기를 통과시키려고 검사기를 바꾸지 않는다 — 막히면 문항을 고친다.
- **이미 있는 120문항은 한 글자도 바꾸지 않는다**(id · 내용 · 점수 모두 — 학생 기록이 id 에 붙어 있다).
- `topik-writing.js` 말고 다른 파일을 고치지 않는다(`index.html` · `llms.txt` · `app.module.js` · 자국 · 생성된 쪽 모두).
- **파일을 CRLF 로 저장하지 않는다**(LF 그대로). UTF-8. 값 안에 홑따옴표를 쓰면 이스케이프를 지킨다(이미 있는 문항처럼).
