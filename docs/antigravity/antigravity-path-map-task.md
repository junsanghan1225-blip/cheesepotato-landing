# 안티 그래비티 지시서 — 학습 길: 레슨마다 붙일 문법 검토(레슨 401개)

브랜치: `path-map` (main 에서 새로). **JSON 하나만 만든다** — `docs/path-map.json`. 도구(`tools/`) · 생성물(`*.js`)은 고치지 말 것.

## 무엇을 위한 것인가
사이트 첫 화면의 「학습 길」(기초 · 중급 · 고급)은 코스 레슨을 한 줄로 이어 놓은 것이다. 레슨 하나가 「한 걸음」이고,
걸음마다 **① 이 레슨의 핵심 문법 설명 → ② 레슨으로 연습 → ③ 그 문법의 단어** 순서로 보인다.
지금 ①의 문법은 기계가 골랐다(`path-map.js` — 레슨 본문에서 문법 꼴이 많이 나온 것 위에서 둘). 틀린 짝 · 빠진 짝이 있다.

## 할 일
1. `path-map.js` 의 `PATH_GRAMMAR`(레슨 id → 문법 id 목록)를 `courses.js`(레슨 제목 · 본문)와 `sentences.js` · `sentences-*.js`(문법 id · 이름 · 뜻)로 대조한다.
2. 레슨 401개 **전부**에 대해 「이 레슨이 실제로 가르치는 문법」을 정해 `docs/path-map.json` 에 적는다.
```json
{
  "_note": "레슨 id → 그 레슨의 핵심 문법 id(0~2개, 중요한 순). 문법이 없는 레슨(한글 낱자 · 발음 등)은 []",
  "hangul-01": [],
  "im-02-02-01": ["<SB id>", "<SB id>"]
}
```
- 문법은 **0~2개, 가장 중요한 것부터**. 레슨 제목에 문법 이름이 있으면 그것이 첫째.
- 코스 단계보다 높은 문법은 넣지 않는다(초급 레슨에 고급 문법 X). 문법 id 의 단계는 `lv`(beginner · intermediate · advanced).
- 조사(을/를 · 은/는 · 이/가 · 에)는 **그 레슨이 조사를 가르치는 레슨일 때만**.
- 맞는 문법이 SB 목록에 없으면 `[]` 로 두고, 그 레슨 id 를 `"_missing": {"레슨 id": "필요한 문법 이름"}` 에 적는다(Claude 가 나중에 본다).
- 확실하지 않은 것은 `"_check": ["레슨 id", …]` 에 모은다.

## 확인 · 끝나면
`node tools/build-path-map.mjs` — 없는 레슨 id · 문법 id 가 있으면 오류로 알려 준다. 오류가 없으면 `docs/path-map.json` 만 커밋 · 푸시.
(path-map.js 와 자국은 Claude 가 main 기준으로 다시 만든다.)
