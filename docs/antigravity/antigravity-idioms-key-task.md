# 안티 그래비티 지시서 — 「필수 관용 표현」 빈출도 다시 판단(1차) + 운영자가 고른 「중요 표현」 정리(2차)

> 운영자 2026-11-03 「미니 테스트 전에 중요 표현만 정리해서 넣어 주자 · 맥락이 제일 중요하고 어떤 표현과 주로 같이 쓰는지 · 관용 표현 빈출도 다시 한번 판단」. 이 파일과 `AGENTS.md` 를 같이 붙여 넣고, 첫 줄은 「AGENTS.md 를 먼저 읽고, 이 지시서대로만 해」.
> **두 번에 나눠 보낸다**(운영자 2026-11-03 「빈출도나 이런 건 안티가 반영하고」): **1차 = 작업 1(빈출도)** — 결과 `docs/idioms/freq.json`. Claude 가 그 결과를 운영자의 고르는 화면에 넣고, 운영자가 단원마다 3~5개를 고른 다음 **2차 = 작업 2** 를 따로 보낸다 — 결과 `docs/idioms/key-expressions.json`.
> 브랜치는 1차 `ag/idioms-freq` · 2차 `ag/idioms-key`(main 에서 새로). 다른 파일은 건드리지 않는다. **지금(1차)은 작업 1 만 한다.**

## 책이 지금 어떻게 생겼나
- 표현 449개(관용구 150 · 속담 150 · 사자성어 149)를 15개씩 **30단원**(`ex-01` ~ `ex-30`)으로 묶었다. 자료: `vocab/data/expressions.json`(`id` · `head` · `meaning` · `examples` · `dialog` · `rel` · `note` …). 책 틀: `docs/books/korean-idioms.json`(단원 = `inline['ex-01']` …, 표현 = `sections[0].entries` 의 `ko`).
- 단원은 지금 **급(lv 3~6) → 주제** 순으로 묶였고, 「급」은 어려움이지 **빈출이 아니다**. 단원 끝에 「단원 점검」(미니 테스트: 뜻 짝짓기 + 대화 빈칸)이 있다.
- 단원의 표현 목록 보기: `node -e "const j=require('./docs/books/korean-idioms.json');for(const [id,u] of Object.entries(j.inline)){console.log(id,u.sections[0].entries.map(e=>e.ko).join(' · '))}"`

## 작업 1 (1차 — 지금) — 빈출도 다시 판단(449개 전부)
표현마다 **빈출도 `freq`**(3 · 2 · 1)와 한 줄 근거 `why` 를 쓴다.
- **3 = 아주 자주**: 일상 대화와 신문 · 칼럼 · 수필에서 매우 흔하고, TOPIK II 읽기 · 쓰기에서 알아 두면 바로 도움이 되는 표현.
- **2 = 자주**: 흔하지만 상황이 조금 한정되거나 글에서 더 자주 보이는 표현.
- **1 = 알아 두면 좋음**: 비교적 드물거나 옛 말투 · 한정된 상황이어서 우선순위가 낮은 표현.
- 판단 기준(세 가지를 같이): ① 일상에서 얼마나 자주 듣는가 ② 글(신문 · 칼럼 · 수필 · 설명문)에서 얼마나 자주 나오는가 ③ 초 · 중급 학습자가 먼저 알아야 하는가. **실제 TOPIK 기출을 옮기거나 인용하지 않는다.**
- **수치를 지어내지 않는다**(「코퍼스에서 ○○회」 같은 말 금지). 확신이 낮으면 `conf` 를 `check` 로.
- 분포 권장: 3 약 25~30% · 2 약 45% · 1 나머지. 한쪽으로 몰리지 않게(특히 사자성어는 글에 치우치므로 3 이 많지 않게).
- 사자성어 · 속담 · 관용구 **세 갈래 안에서** 비교해 매긴다.

## 작업 2 (2차 — 운영자가 고른 뒤 따로 보낸다. 1차에서는 하지 않는다) — 운영자가 고른 「중요 표현」 정리
**어떤 표현을 정리할지는 운영자가 고른다.** 단원마다 3~5개, 고른 목록은 `docs/idioms/picks.json`(`{"ex-01": ["숨을 쉬다", "한눈을 팔다", …], …}` — Claude 가 main 에 넣어 둔다). **그 목록의 표현만** 쓴다(없는 표현을 더하거나 빼지 않는다). 단원 점검(미니 테스트) 바로 앞쪽에 실을 정리다.
표현마다:
- `ctx` — **맥락**(가장 중요). 어떤 상황 · 누구에게 · 어떤 느낌(칭찬 · 충고 · 후회 · 걱정 · 격식 · 가벼운 말 …)에서 쓰는지 한 줄(한국어, 쉬운 말 40자 안팎) + 영어 한 줄.
- `with` — **자주 같이 쓰는 말** 3개. 앞에 오는 낱말 · 주어 · 이어지는 문법 꼴. 예: 「한눈을 팔다」 → 「운전할 때」 · 「공부하다가」 · 「한눈을 팔면」. **실제로 흔한 짝만**, 억지로 짓지 않는다. 각 항목 12자 안팎 + 영어 뜻.
- `note` — (선택) 조심할 점 한 줄: 윗사람에게 쓰면 안 됨 · 글에서만 · 부정 느낌 · 비슷해 보이지만 다른 표현.
- `compare` — **비슷한 표현과 비교**(운영자 2026-11-03 「비슷한 표현 있으면 비교하는 것까지」). **정말 비슷한 표현이 있을 때만**(없으면 이 칸을 빼고 `compare:[]`). 최대 2개. 항목마다:
  - `head` 비슷한 표현(자료의 `rel.syn` · 같은 책 안의 표현이면 먼저. 책에 있으면 `unit` 에 단원 번호).
  - `diff` **어떻게 다른지** 한 줄(한 · 영): 뜻의 범위 · 느낌(긍정 · 부정) · 격식 · 글 / 말 · 쓰는 상황.
  - `use` **언제 이쪽, 언제 저쪽**을 고르는지 한 줄(한 · 영) — 예: 「가볍게 말할 때는 A, 글에서는 B」.
  - 둘이 **바꿔 써도 되는지**도 쓴다(`swap`: `yes` · `partly` · `no`).
- **예문은 새로 만들지 않는다**(책에 이미 예문 둘이 있다). 이 정리는 「맥락 · 같이 쓰는 말」만.
- 사자성어는 `with` 를 「자주 쓰는 틀」로 써도 된다(예: 「-의 효과」 · 「-하는 모습」 · 「-라고 할 수 있다」).
- 한 단원 정리는 **쪽 한 장(비교가 많으면 두 장까지)**: 표현 최대 5개 × (ctx 한 · 영 + with 3 + note + 비교 최대 2) — 길게 쓰지 않는다. 비교는 **정말 헷갈릴 만한 짝**만. (그림은 따로 Gemini 가 그린다 — 안티는 신경 쓰지 않는다.)

## 지킬 것
- **사실을 지어내지 않는다**: 기관 · 법 · 연도 · 유래 이야기 · 통계. 유래가 확실하지 않으면 쓰지 않는다. 확신이 낮으면 `conf:"check"`.
- 한국어는 **선생님 말투, 쉬운 말**. 광고체 · 줄표(**—**) 쓰지 않는다(책 검사에 걸린다). 「A, B, C」 세 개 나열을 습관처럼 쓰지 않는다.
- 영어는 학습자가 읽는 쉬운 영어. 표현의 뜻을 영어로 다시 설명하지 말고 **쓰는 장면**을 쓴다.
- `head`(표제어)는 자료의 글자 그대로(책의 `ko` 와 같게).

## 돌려줄 모양
**1차** — `docs/idioms/freq.json`(배열, 449개 전부):
```json
[
  { "id": "x4-001", "head": "일석이조", "freq": 3, "why": "신문 · 칼럼 · 일상에서 모두 흔한 말", "conf": "high" }
]
```
- `id` 는 `vocab/data/expressions.json` 의 `id`, `head` 는 책의 표제어 글자 그대로. `conf` 는 `high` · `mid` · `check`.

**2차** — `docs/idioms/key-expressions.json`(`picks.json` 의 단원 · 표현과 똑같이):
```json
{
  "units": {
    "ex-01": [
      { "head": "한눈을 팔다",
        "ctx": { "ko": "해야 할 일에서 눈을 돌릴 때(운전 · 공부)에 쓰는 가벼운 꾸중 · 걱정의 말", "en": "Said when someone's attention drifts from what they should be doing; a light scolding or warning." },
        "with": [ { "ko": "운전할 때", "en": "while driving" }, { "ko": "공부하다가", "en": "while studying" }, { "ko": "한눈을 팔면", "en": "if you get distracted" } ],
        "note": { "ko": "윗사람에게는 「집중이 흐트러지셨다」처럼 돌려 말해요.", "en": "To a superior, say it indirectly." },
        "compare": [ { "head": "딴생각하다", "unit": null, "diff": { "ko": "「딴생각하다」는 머릿속 생각이 다른 데 가 있는 것, 「한눈을 팔다」는 눈 · 주의가 딴 데로 간 것", "en": "“딴생각하다” is about the mind wandering; “한눈을 팔다” is about attention or eyes leaving the task." }, "use": { "ko": "운전 · 길 건너기처럼 눈이 중요한 상황은 「한눈을 팔다」", "en": "Use “한눈을 팔다” where eyes matter, such as driving." }, "swap": "partly" } ],
        "conf": "high" }
    ]
  }
}
```

## 확인 · 끝나면
**1차:** ① `JSON.parse(require('fs').readFileSync('docs/idioms/freq.json','utf8'))` 로 열리는지. ② 449개 모두 있는지, `freq` 3 · 2 · 1 의 개수, `conf:"check"` 개수를 답글에 적는다. ③ 파일만 커밋 · 푸시.
**2차:** ① `key-expressions.json` 이 열리는지. ② `picks.json` 의 표현 수와 `units` 의 표현 수가 같은지 세어 답글에 적는다. ③ 파일만 커밋 · 푸시.
자국 · 생성 도구는 Claude 가 한다.
**Claude 가 받으면:** 1차 → 빈출도를 운영자의 고르는 화면(`node tools/idioms-pick-html.mjs out.html docs/idioms/freq.json`)에 넣어 보낸다. 2차 → ① 빈출 표시(최다 빈출 표시) ② 단원 점검 바로 앞에 「중요 표현」 쪽 ③ 단원 안 표현 순서를 빈출 순으로 바꿀지 운영자와 정함 ④ 그림은 Gemini 결과가 오면 중요 표현 쪽에 얹음 ⑤ 책 · 사이트 다시 만들기.
