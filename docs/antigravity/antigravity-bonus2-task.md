# 안티 그래비티 작업 지시 — 책 QR 보너스 연습 (조사 워크북 · TOPIK II 쓰기 51~52번)

> 이 파일과 `AGENTS.md` 를 같이 붙여 넣는다. 첫 줄: 「AGENTS.md 를 먼저 읽고, 이 지시문대로만 해. 이번 묶음은 **<책 id> <묶음 이름>** 이야.」
> 첫걸음 워크북 보너스(`antigravity-bonus-task.md`)와 같은 틀이다. 책의 QR 을 찍으면 단원마다 **낱말(표현) 카드 · 퀴즈 · 빈칸 쓰기**가 열린다. 책 안의 연습과 겹치지 않는 **새 문항**이어야 한다.

## 무엇을
- 결과 파일: **책마다 한 파일** — `docs/bonus/particles-workbook.json` · `docs/bonus/topik2-writing-51-52.json`. 파일이 없으면 아래 모양으로 만든다(`"_note"`, `"book"`, `"units": {}`). 묶음마다 이어서 더하고, 이미 있는 단원은 건드리지 않는다. 브랜치 `ag/bonus2-N`.
- 모양(첫걸음 보너스 `docs/bonus/first-steps-workbook.json` 과 같다. 시범으로 그 파일의 `greetings-self-introduction` 을 본다):

```json
{
  "_note": "책 QR 보너스 연습 — 안티 작성 · Claude 검토",
  "book": "particles-workbook",
  "units": {
    "단원id": {
      "cards": [ { "ko": "저는 학생이에요", "en": "I am a student." } ],
      "quiz":  [ { "q": "영어 질문", "opts": ["보기1", "보기2", "보기3", "보기4"], "a": 1, "why": "영어 한두 문장 풀이" } ],
      "fill":  [ { "q": "저는 학생___ 아니에요.", "en": "I am not a student.", "a": ["이"] } ]
    }
  }
}
```
- 개수: `cards` 8개(6~12), `quiz` 5개(4~8, 보기 3~4개), `fill` 5개(4~8). `a`(quiz)는 정답 보기의 번호(0부터). `fill.a` 는 **글 배열**(허용하는 답이 둘 이상이면 모두).

## 규칙 (꼭 지킬 것)
1. **책 안 연습과 겹치지 않게.** 그 단원의 책 쪽(조사 책은 `docs/books/particles-workbook.json` 의 `inline.<단원id>`, TOPIK 쓰기 책은 `inline.i<단원id>` 와 `groups.<단원id>`)에 있는 문장 · 문항과 같은 문장을 쓰지 않는다(검사가 막는다). TOPIK 쓰기 책은 책에 실린 문항(`topik-writing.js` 의 `w51-N` · `w52-N`)도 베끼지 않는다.
2. **전부 창작.** 실제 TOPIK 기출 문장을 쓰지 않는다. 기관 · 날짜 · 장소를 지어낼 때는 어디에도 실제로 있을 법한 이름을 피한다(예: 「한빛 도서관」 같은 가상 이름).
3. **그 단원까지 배운 낱말 · 문법 안에서.** 책 순서는 `docs/books/<책 id>.json` 의 `parts`. 새 말은 그 단원 주제와 맞는 것만.
4. **한국어는 자연스럽고 정확하게.** 의심되면 그 문항은 빼고 `docs/antigravity/bonus-notes.md` 에 단원 id 와 한 줄로 적는다.
5. 퀴즈는 정답이 **하나**만 맞는 문제. 틀린 보기도 그럴듯해야 하고, 풀이(`why`)는 왜 맞는지 영어 한두 문장. 보기 앞에 번호를 쓰지 않는다(쪽이 ①②③ 을 붙인다).
6. 빈칸 `fill.q` 에 `___` 가 **하나**. 정답은 한글로 칠 수 있는 짧은 말. 영어 뜻(`en`)은 꼭.
   - **정답이 하나뿐**이어야 한다. 「은/는」 「이/가」 처럼 둘 다 되는 문장이면 `a` 에 둘 다 적거나, 한 가지만 되는 문장으로 바꾼다.
   - 붙여 쓰면 틀린 말이 되는 답을 쓰지 않는다.
7. 문장은 **존댓말(해요체 · 합니다체)**. 반말(`-야`, `-거야`)은 쓰지 않는다. 단, TOPIK 쓰기 책은 문체 자체가 주제이므로 단원이 요구하는 문체(안내문 -ㅂ니다체 · 설명문 -(느)ㄴ다체)를 정확히 따른다.
8. 줄표(—)를 쓰지 않는다. 다른 파일 · 이미 있는 단원을 고치지 않는다.
9. 첫걸음 보너스 1묶음 검토에서 나온 실수를 되풀이하지 않는다: 책 연습에 이미 있는 낱말 · 소리 읽기 문항을 다시 내지 않는다(같은 낱말은 카드에만).

## 책별 안내

### 조사 워크북 (`particles-workbook`) — 단원 29개
- **카드**: 그 조사가 들어간 짧은 문장 또는 조사 + 낱말 짝(`ko` 한국어, `en` 영어 뜻). 조사 이름만 늘어놓지 말고 쓰임이 보이게 한다.
- **퀴즈**: 문장에 맞는 조사 고르기 · 뜻이 다른 문장 가르기 · 틀린 문장 찾기.
- **빈칸**: `___` 자리에 조사만 넣는다(받침 따라 갈리는 조사는 `a` 에 모두 적는다).
- `ct-*` 단원(헷갈리는 조사 가르기)은 **비슷한 조사 둘을 나란히 놓고 고르는** 문항이 중심이다. 정답이 하나가 되도록 상황(문장 앞뒤)을 충분히 준다.

### TOPIK II 쓰기 51~52번 (`topik2-writing-51-52`) — 단원 7개
- **카드**: 그 유형에서 자주 쓰는 **문장 틀 · 연결 표현 · 문체 어미**(`ko` 한국어, `en` 용도 영어 설명). 예: 「~ㅂ니다/습니다 (안내문 끝)」 「~ 바랍니다」.
- **퀴즈**: 글의 종류에 맞는 문체 고르기 · 앞뒤에 어울리는 연결 표현 고르기 · 문장 순서 · 어색한 표현 찾기.
- **빈칸**: 짧은 연결 표현 또는 어미 한두 낱말(예: `___ 때문에`). 한 문장 전체를 쓰게 하지 않는다.
- 51번 단원은 -ㅂ니다체(안내문), 52번 단원은 -(느)ㄴ다체(설명문).

## 하는 법
1. `git pull` 로 main 을 받고 브랜치를 만든다.
2. 해당 책의 `docs/bonus/<책 id>.json` 의 `units` 에 단원을 더한다.
3. `node tools/check-bonus.mjs` 가 **OK** 인지 본다(개수 · 보기 번호 · 풀이 · 책 안 문장 겹침 · 줄표).
4. `node tools/build-bonus.mjs` 로 쪽이 만들어지는지 본다. 그다음 **JSON 파일만** 커밋한다(`bonus/` 폴더는 Claude 가 만든다).
- 커밋 메시지: `<책 이름> 보너스 연습 · <단원 id 범위> N단원`. 브랜치를 푸시한다(PR 은 만들지 않는다). 끝나면 한 줄: 「<브랜치> · N단원 · 건너뜀 K · <커밋 앞 7자리> 올림」.
