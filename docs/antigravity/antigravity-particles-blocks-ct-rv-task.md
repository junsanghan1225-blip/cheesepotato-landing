## A. 비교 단원(`ct-*`) 자료 모양
```json
"ct-topic-subject": {
  "compare": [
    { "title": { "ko": "하늘 ○ 파래요", "en": "" },
      "sides": [
        { "label": "은/는", "ko": "하늘은 파래요.", "en": "The sky is blue (a general fact, or in contrast).",
          "chip": "일반적인 사실 · 견줄 때", "mean": "하늘은 원래 파래요.",
          "blocks": [ {"t": "하늘", "role": "주어 말"}, {"p": "은", "role": "주제 조사"}, {"t": "파래요", "role": "서술어"} ] },
        { "label": "이/가", "ko": "하늘이 파래요.", "en": "The sky is blue (I see it now).",
          "chip": "지금 눈에 보이는 것", "mean": "지금 보니 하늘이 파래요.",
          "blocks": [ {"t": "하늘", "role": "주어 말"}, {"p": "이", "role": "주어 조사"}, {"t": "파래요", "role": "서술어"} ] } ] }
  ],
  "rule": { "ko": "「누가 · 뭐가」로 물으면 이/가로 답해요. 이미 아는 것을 말하거나 둘을 견주면 은/는.", "en": "…" },
  "situations": [
    { "ctx": "친구가 물어요: 「누가 학생이에요?」", "q": "내 대답은?", "opts": ["저는 학생이에요.", "제가 학생이에요."], "answer": 2, "why": "A who-question is answered with 이/가." }
  ],
  "fill2": [
    { "ko": "저는 선생님이고 제 친구는 학생이에요.", "en": "I am a teacher, but my friend is a student.",
      "blocks": [ {"t": "저", "role": "나"}, {"p": "는", "role": "주제 조사", "blank": true}, {"t": "선생님", "role": "말"}, {"t": "제 친구", "role": "주어 말"}, {"p": "는", "role": "주제 조사", "blank": true}, {"t": "학생이에요", "role": "서술어"} ] }
  ],
  "pool": ["은", "는", "이", "가"],
  "explain": { "q": "민수는 왔어요. / 민수가 왔어요. 두 문장은 어떻게 다를까요?", "en": "Minsu came. How do the two sentences differ?",
    "opts": ["는: 민수에 대해 말해요", "가: 누가 왔는지 알려 줘요"], "answer": 2, "why": "…" }
}
```
- `compare.sides` 는 **2~3개**(와/과 · 하고 · (이)랑, 도 · 만 · 밖에 처럼 셋을 가르는 단원은 3개). 각 side 의 `blocks` 를 합친 글 = `ko`(마침표 · 쉼표 · 느낌표는 무시).
- **같은 문장에서 조사만 바꾼 것**이 비교의 중심이다: 한 `compare` 안에서 `sides` 의 낱말 블록(`t`)은 가능한 한 같게 하고, 달라지는 것은 조사 블록(`p`)과 그 뜻 풀이뿐. (다른 낱말이 꼭 필요한 비교 — 예: 에게/한테 vs 에는 사람 · 물건이 다르다 — 면 낱말만 바꾸고 `title` 에 이유를 쓴다.)
- `title.ko` 는 문장의 조사 자리를 `○` 로 비운 글(「하늘 ○ 파래요」), `title.en` 은 비워 둬도 된다.
- `chip` 은 7자 안쪽의 짧은 꼬리표(한국어), `mean` 은 한 줄 설명(한국어), `en` 은 영어 뜻.

| 자료 | 개수 | 규칙 |
|---|---|---|
| `compare` | 3 | 서로 다른 장면 3개. 각각 `sides` 2~3. |
| `rule` | 1 | 한 줄 요약(한국어 + 영어). 단원의 「The difference」 글과 맞아야 한다. |
| `situations` | 4 | 상황 한 줄(`ctx`) + 문제(`q`, 빈칸은 `___`) + 보기 2개(`opts`) + `answer`(번호 1부터) + `why`(영어 한 줄). **정답은 하나**여야 한다. 보기는 문장 전체이거나 조사 하나 중 하나로 통일(한 단원 안에서 섞어도 좋지만 문제 하나 안에서는 통일). |
| `fill2` | 2 | 블록 문장 하나에 **비운 조사 블록 1~2개**(`blank: true`). 하나는 1칸, 하나는 2칸(대조 문장)이 좋다. 정답은 `pool` 안에서. 완성 문장을 `ko` 에 적는다. |
| `pool` | 4 | 이 단원에서 비교하는 조사 + 헷갈리는 조사로 4개. |
| `explain` | 1 | 같은 문장에 조사만 바꾼 두 문장의 차이를 고르기(보기 2개) + 한 줄 이유. 책에는 「왜?」 줄이 붙는다. |

## B. 종합 연습(`rv-*`) 자료 모양
```json
"rv-1": {
  "choose": [ { "q": "책 위___ 가방이 있어요.", "en": "A bag is on the desk.", "opts": ["에", "에서", "를"], "answer": 1, "why": "있다 with a place takes 에." } ],
  "fix": [
    { "ko": "저는 한국어를 배워요.", "en": "I learn Korean.",
      "blocks": [ {"t": "저", "role": "나"}, {"p": "는", "role": "주제 조사"}, {"t": "한국어", "role": "목적어 말"}, {"p": "가", "role": "목적 조사", "wrong": true, "right": "를"}, {"t": "배워요", "role": "서술어"} ] }
  ],
  "fill": [ { "ko": "…", "en": "…", "blocks": [ … ] } ],
  "pool": ["…", "…", "…", "…"]
}
```
- `fix` 는 **틀린 조사 블록 하나**가 있는 문장이다. 틀린 블록에 `"wrong": true` 와 `"right": "<맞는 조사>"` 를 붙인다(블록의 `p` 는 틀린 글자). `ko` 는 **고친 뒤 올바른 문장**이다(합친 글 검사는 `wrong` 블록의 `p` 를 `right` 로 바꿔서 한다).
- `choose` · `fill` 규칙은 1차 지시문과 같다(`choose` 의 `opts` 2~4개, 정답 하나 · `fill` 의 비운 블록 1~2개 · `pool` 4개).
- **함정**: 처음 떠오르는 답이 틀리는 문장을 고른다 — ㄹ 받침 + 으로(→ 로), 에게/한테 vs 에(물건 · 장소), 의문사 뒤 이/가, 에서 vs 에, 도 · 만 뒤 조사 겹침(에만 · 에서도), 은/는 vs 이/가 등. 함정 문제는 `why` 에 「흔한 실수」를 한 마디 넣는다.

| 단원 | 범위(이 단원에서 쓸 수 있는 조사) | `choose` | `fix` | `fill` |
|---|---|---|---|---|
| `rv-1` | 이/가 · 은/는 · 을/를 · 의 (pt-26-1·2·3·5) | 6 | 4 | 4 |
| `rv-2` | 위 + 에 · 에서 · 에게/한테 · 부터 · 까지 (pt-26-6~10) | 6 | 4 | 4 |
| `rv-3` | 위 + 와/과 · 하고 · (이)랑 · 도 · 만 · 밖에 · (이)나 (pt-26-4·11~13·15·16) | 6 | 4 | 4 |
| `rv-4` | 위 + (으)로 · 쯤 · 처럼/같이 · 보다 · 마다 (pt-26-14·17~20) | 6 | 4 | 4 |
| `rv-5` | 비교 단원 9개에서 가른 조사 쌍(은/는 vs 이/가, 에 vs 에서 …) | 6 | 4 | 4 |
| `rv-6` | 책 전체 | 6 | 4 | 4 |

- 한 `rv` 안에서 **같은 조사만 반복하지 않는다**(한 조사가 `choose` · `fix` · `fill` 합쳐 4번을 넘지 않게). 그 범위의 조사를 골고루.
- 같은 책 앞 단원(`pt-26-*` · `ct-*` · 이미 쓴 `rv-*`)에 나온 문장을 그대로 쓰지 않는다 — **문장은 전부 새로 만든다.**

## 규칙 (1차와 같다. 꼭 지킬 것)
1. **한국어가 자연스럽고 정답이 하나.** 의심스러우면 빼고 `docs/antigravity/particles-blocks-notes.md` 에 단원 id 와 한 줄로 적는다. 특히 은/는 · 이/가 · 에/에서 · 도/만은 문맥에 따라 둘 다 맞기 쉬우니 **상황 한 줄(`ctx`)로 정답을 하나로 못 박는다.**
2. **그 단원까지 배운 조사 · A1~A2 낱말만.** 위 범위 표를 넘지 않는다.
3. **실제 TOPIK · EPS 기출 금지,** 이름은 민수 · 지영 · 수진 같은 흔한 이름만, 기관 · 전화번호 · 실제 장소 이름 금지.
4. 영어 뜻은 자연스러운 한 문장. 줄표(—) 금지(쉼표 · 쌍점으로). 광고체 금지.
5. 역할 이름은 1차 지시문의 목록에서만.
6. 다른 파일 · 다른 단원 · 이미 있는 키를 고치지 않는다.

## 하는 법
1. `git pull` 로 main 을 받고 브랜치를 만든다(비교는 `ag/particles-blocks-ct-1`, 종합은 `ag/particles-blocks-rv-1`).
2. 단원마다 `inline.<id>` 의 글 · 표를 읽고 만든다. 한 번에 비교 4~5개 또는 종합 3개씩 올려도 좋다.
3. `docs/books/particles-workbook.blocks.json` 에 키를 더한다(JSON 문법 주의).
4. 올리기 전에 **`node tools/check-particles-blocks.mjs`** 가 통과해야 한다(이번 지시문 모양을 검사하는 부분은 Claude 가 먼저 넣어 둔다).
5. 스스로 확인: 블록을 합쳐 소리 내어 읽어 보기 · `situations` / `choose` 의 정답이 정말 하나인지 · `fix` 의 틀린 조사가 정말 틀린지.
