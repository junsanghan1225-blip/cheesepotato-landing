# 안티 그래비티 작업 지시 — 문법별 TOPIK 스타일 문항 (TOPIK 문장이 없는 문법 218개)

> 이 파일과 `AGENTS.md` 를 같이 붙여 넣는다. 첫 줄: 「AGENTS.md 를 먼저 읽고, 이 지시문대로만 해. 이번 묶음은 **<단계 · 문법 id 범위>** 야.」
> 브랜치: `ag/grammar-topik-N` (main 에서 새로). 운영자 2026-10-18 「문법마다 TOPIK 문장이 있고 없고 해 — 문법별 TOPIK 스타일 문항을 만들어서 바로 TOPIK 으로 넘어가게」.

## 왜
문법 화면의 「이렇게 쓰였어요」는 **우리 TOPIK 문항 안에서 그 문법이 쓰인 문장**을 찾아 보여 주고, 🎯 을 누르면 그 문항으로 넘어간다. 그런데 문법 290개 중 72개만 찾아지고 **218개는 TOPIK 문장이 하나도 없다**(초급 71 · 중급 75 · 고급 72). 그 문법이 **시험에서 어떻게 묻는지**를 보여 주는 TOPIK 모양 문항을 문법마다 만들어 채운다.

## 무엇을
`docs/grammar-topik.json` 에 **문법 id 마다 문항 2개**를 더한다(이미 있는 줄은 건드리지 않는다). 모양:
```json
"59-1": [
  { "stem": "이 방은 넓을 ( ) 밝아요.",
    "options": ["뿐만 아니라", "때문에", "대신에", "만큼"],
    "answer": 0,
    "sentence": "이 방은 넓을 뿐만 아니라 밝아요.",
    "en": "This room is not only spacious but also bright.",
    "why": "「-(으)ㄹ 뿐만 아니라」는 앞의 일에 뒤의 일을 더합니다. 앞뒤가 같은 방향(넓다 · 밝다)이라 알맞습니다." } ]
```
- 형식은 TOPIK 읽기의 「( )에 들어갈 가장 알맞은 것을 고르십시오.」다. `stem` 에 `( )` 가 **딱 하나**, `options` 는 **서로 다른 네 개**, `answer` 는 정답 번호(0~3), `sentence` 는 **정답을 ( ) 에 넣은 완성 문장**(그 문법의 꼴이 그대로 들어 있어야 한다).
- 문항은 **2개를 서로 다른 모양**으로: 하나는 문법 부분(어미 · 조사)이 정답인 문항, 하나는 다른 말이 정답이고 문법이 **정답 문장 속에 들어 있는** 문항(예: 「( )를 위해서」 앞뒤 낱말을 고르게 하되 완성 문장에 그 문법이 쓰임).
- 문법 이름 · 뜻 · 예문 · 지금 있는 문장: `node tools/show-grammar.mjs <id>`. 아직 없는 문법 목록: `node tools/show-grammar.mjs --topik-todo beginner|intermediate|advanced`.

## 꼭 지킬 것 (검사 `node tools/check-grammar-topik.mjs` 가 막는 것 + 사람이 보는 것)
1. **정답은 하나뿐** — 오답 셋은 **문법적으로 또는 뜻으로 분명히 틀려야** 한다. 정답과 비슷한 문법(예: 「-아서」 ↔ 「-(으)니까」)을 오답에 쓰되 **그 문장에서는 안 되는 이유**가 있어야 한다. 둘 다 말이 되는 문항은 되돌려 보낸다(검사가 못 거르니 사람이 본다).
2. **`stem` 에 정답을 넣은 문장 = `sentence`**(띄어쓰기는 안 따진다). 붙여 쓰는 꼴(「맛있을뿐더러」)은 `( )` 앞에 띄어 쓰지 말고 `맛있을( )` 로 쓴다.
3. **그 문법의 꼴이 `sentence` 에 실제로 들어 있다**(검사). 이름에서 꼴을 못 찾는 문법(「숫자」 · 「날짜와 요일」 · 「A/V-아/어요」 …)은 검사가 건너뛰니 **직접 틀리지 않게** 쓴다.
4. 급수에 맞는 말: 초급 문법은 TOPIK Ⅰ 수준(어휘 · 문장이 쉽고 9어절 안쪽), 중급 · 고급은 TOPIK Ⅱ 수준(16어절 안쪽). 앞의 `show-grammar` 의 예문 · 대화와 **같은 문장을 쓰지 않는다**(검사).
5. `en` 은 자연스러운 영어 한 문장(줄임말 따옴표 · 문장 끝 마침표). `why` 는 한국어로 「왜 이 보기가 정답인지」 한두 문장.
6. **기출 아님** — 전부 창작. 실제 TOPIK · EPS 문항을 옮기지 않는다. 기관 · 제도 · 숫자는 일반 말만, 지어낸 사실을 쓰지 않는다.
7. 문장마다 다른 낱말 · 상황. 같은 틀에 낱말만 바꾼 문항은 되돌려 보낸다. 다른 문법에 같은 문장이 있으면 안 된다(검사).

## 올리기
- 검사: `node tools/check-grammar-topik.mjs` 통과 → 커밋(`docs/grammar-topik.json` 만). 메시지: `문법별 TOPIK 문항 N묶음 — <id 범위> (X개 문법 · Y문항)`. 푸시까지 해야 끝(PR 은 만들지 않는다).
- 묶음: 한 번에 문법 25~30개, 초급(71개)부터 → 중급(75) → 고급(72). 묶음마다 `ag/grammar-topik-1`, `-2` …
- 그다음은 Claude 가 검토해, 이 문항들을 TOPIK 연습(문법 읽기 문항)에 넣고 문법 화면 「이렇게 쓰였어요」에서 🎯 로 바로 풀게 이어 붙인다.
