# 안티 그래비티 지시서 — 문법 채우기(비교 짝 · 바꿔 쓰기 · 연습 문장)

브랜치: `grammar-fill` (main 에서 새로). **도구(`tools/`) · 생성물(`*.js`)은 고치지 말 것** — JSON 만 고친다.
모든 문장은 **창작**. 실제 TOPIK 기출 문장을 옮기지 않는다. 확실하지 않은 것은 항목에 `"note":"운영자 확인"` 을 단다.
문법 이름 · 뜻은 `sentences.js`(SB_CATS) 의 그 id 를 보고 맞춘다.

## (가) 헷갈리는 문법 비교 40쌍 → `docs/grammar-pairs.json`
이미 있는 2쌍(`aseo-nikka`, `goitda-aeoitda`)과 같은 모양으로 **40쌍 더**. 학생이 실제로 자주 헷갈리는 짝만
(예: -는데/-지만, -(으)ㄹ게요/-(으)ㄹ 거예요, -고 나서/-(으)ㄴ 후에, 이/가 vs 은/는, -아/어도 되다/-(으)면 되다 …).
```json
{"id":"영문-소문자-짝","a":"<SB id>","b":"<SB id>",
 "title":{"ko":"-아서/어서 vs -(으)니까","en":"…"},
 "gist":{"ko":"한 줄 요약","en":"…"},
 "diff":[{"ko":"차이 1","en":"…"}, …2~4개],
 "ex":{"a":"A 예문","b":"B 예문"},
 "quiz":[{"q":"빈칸이 ___ 하나인 문장","ok":"빈칸에 들어갈 말","ans":"a|b","why":"이유(한국어 한 문장)"}, …4~8개]}
```
- quiz 는 **한쪽만 맞는** 문장으로(둘 다 되면 안 됨). a · b 정답이 반반쯤 섞이게.
- 두 id 는 반드시 SB_CATS 에 있는 것. 검사: `node tools/build-grammar-pairs.mjs --check`.

## 끝나면
`node tools/build-grammar-pairs.mjs && node tools/build-grammar-drill.mjs && node tools/build-grammar-usage.mjs` 를 돌려 보고
오류가 없으면 브랜치에 커밋 · 푸시. 자국(stamp)은 Claude 가 main 기준으로 다시 찍는다.
