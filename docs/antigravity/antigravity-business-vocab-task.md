# 안티 그래비티 작업 지시 — 비즈니스 한국어 회화 단어장 600개 (200개 한 묶음)

> 이 파일과 `AGENTS.md` 를 같이 붙여 넣는다. 첫 줄: 「AGENTS.md 를 먼저 읽고, 이 지시문대로만 해. 이번은 **N묶음**이야.」
> 운영자 2026-10-31 「비즈니스 한국어 회화 단어장 — 단어는 안티로 뽑고 검수하고 진행」. 1묶음 = 1~200 · 2묶음 = 201~400 · 3묶음 = 401~600. 브랜치: `ag/business-vocab-N`
> 결과 파일: `vocab/data/business.json`(배열, 묶음마다 뒤에 이어 붙인다 — 앞 묶음을 고치지 않는다). 검사: `node tools/check-business-vocab.mjs`

## 무엇을 · 누구에게
회사에서 한국어로 일하는 외국인(통번역 · 한국 회사 취업 · 한국 거래처)과 한국어 학습자를 위한 **회화 단어장**이다. TOPIK 시험 낱말이 아니라 **일터에서 실제로 쓰는 말**을 뽑는다.
책 한 권 = 30단원 × 20개. 단원은 **상황**(예: 인사 · 소개, 전화, 이메일, 회의, 보고, 일정 조정, 출장, 회식, 면접, 협상, 사과 · 거절, 칭찬 · 감사 …) 한 가지씩이다.

## 모양 — `vocab/data/business.json` (배열, 한 줄 = 한 낱말 · 표현)
```json
{
  "id": "bw-001",                  // bw-001 … bw-600 (세 자리, 바꾸지 않는다)
  "unit": 1,                       // 단원 1~30 (한 단원 = 20개, 묶음마다 10단원 … 아래 「단원」 표)
  "head": "회의록",                // 표제(사전형. 표현은 「말씀 좀 여쭙겠습니다」처럼 기본 문장 꼴도 가능)
  "pos": "명사",                   // 명사 · 동사 · 형용사 · 부사 · 표현(관용 · 문장 표현)
  "en": "meeting minutes",         // 영어 뜻(짧게, 업무에서 쓰이는 뜻)
  "lv": 2,                         // 비즈니스 한국어 난이도 1(기초 · 매일 쓰는 말) · 2(보통) · 3(고급 · 격식 · 문서)
  "register": "formal",            // formal(보고 · 문서 · 윗사람) · neutral(동료) · casual(친한 동료 · 구어)
  "situation": "meeting",          // 단원 상황 꼬리표 하나(아래 목록)
  "examples": [
    ["회의가 끝나면 제가 회의록을 정리해서 공유하겠습니다.", "After the meeting I will write up the minutes and share them."],
    ["회의록은 오늘 안으로 메일로 보내 주세요.", "Please send the minutes by email today."]
  ],
  "dialog": [["A", "회의록은 누가 작성하나요?"], ["B", "이번에는 제가 맡겠습니다."]],
  "note": "「회의록을 작성하다 · 공유하다」처럼 붙어 다녀요. 격식 있는 자리에서는 「작성하겠습니다」.",   // 한 줄, 높임 · 붙는 말 · 헷갈림. 없으면 ""
  "polite_alt": "",                // 윗사람에게 쓰는 말이 따로 있으면(예: 「밥」 → 「식사」), 없으면 ""
  "src": "창작 예문"
}
```
상황 꼬리표(`situation`): `greeting` 인사 · 소개 / `phone` 전화 / `email` 이메일 · 메신저 / `meeting` 회의 / `report` 보고 · 지시 / `schedule` 일정 · 약속 / `trip` 출장 · 이동 / `dinner` 회식 · 접대 / `interview` 면접 · 채용 / `negotiate` 협상 · 계약 / `apology` 사과 · 거절 / `thanks` 칭찬 · 감사 / `office` 사무실 · 사무용품 / `finance` 비용 · 정산 / `hr` 인사 · 휴가 · 근무 / `sales` 영업 · 마케팅 / `service` 고객 응대 / `it` 컴퓨터 · 시스템 / `manufacturing` 생산 · 품질 / `logistics` 물류 · 무역 / `culture` 직장 문화 · 호칭

## 단원 (30개 · 위 상황이 단원이다)
1묶음(1~10단원) = 인사 · 소개, 전화, 이메일, 회의, 보고 · 지시, 일정 · 약속, 출장 · 이동, 회식 · 접대, 면접 · 채용, 사무실 · 사무용품
2묶음(11~20단원) = 협상 · 계약, 사과 · 거절, 칭찬 · 감사, 비용 · 정산, 인사 · 휴가 · 근무, 영업 · 마케팅, 고객 응대, 컴퓨터 · 시스템, 직장 문화 · 호칭, (1묶음의 인사 · 전화 보충: 자주 쓰는 인사말 · 전화 표현 2단원)
3묶음(21~30단원) = 생산 · 품질, 물류 · 무역, 그 밖의 심화 상황 8단원(운영자 검수 뒤 Claude 가 정한다 — 먼저 1 · 2묶음)
한 단원 20개 안에 **명사 8~10 · 동사 · 형용사 5~6 · 표현(문장째) 4~5개**를 섞는다. 표현(문장째)은 전화 · 메일 · 회의에서 그대로 쓰는 틀이다(「회의 시작하겠습니다」 · 「확인 부탁드립니다」).

## 지킬 것 — 사실 · 매핑 · 질
1. **일터에서 실제로 쓰는 말만.** 사전에 있어도 일터에서 안 쓰는 말은 뺀다. 같은 뜻을 다른 말로 두 번 넣지 않는다.
2. **한국어가 자연스러워야 한다.** 예문은 한국 회사에서 실제로 오갈 만한 문장(너무 책 같은 번역투 금지). 윗사람에게 하는 말에는 높임(-시-, -습니다/-세요)을 바르게, 동료에게 쓰는 말은 구분한다. 확신이 없는 어휘 · 뉘앙스는 `note` 에 단정하지 말고 「~할 때가 많아요」처럼 쓴다.
3. **사실을 지어내지 않는다.** 회사 이름 · 기관 · 법 · 제도 · 요율 · 근로 기준 · 세금 숫자를 쓰지 않는다. 휴가 일수 · 임금 · 법적 의무 같은 말은 낱말 뜻과 예문 문장으로만 다룬다(「연차를 쓰다」는 되지만 「연차는 15일이다」는 안 된다). 예문 속 날짜 · 금액은 예시용 숫자로(실존 회사 · 제품명 금지).
4. **예문에 표제어가 그대로 나오게**(활용형 가능: 어간이 들어가면 된다). 예문 둘은 서로 다른 상황으로. 영어는 자연스럽게, 뜻 풀이만 하지 않는다.
5. `dialog` 는 2줄(A · B) 짧게. 모든 낱말에 넣을 필요는 없고 표현(문장째) 단원에서 우선.
6. **같은 칸을 몰아 쓰지 않는다**: lv 는 1 · 2 · 3 이 모두 나오게(대략 1:2:3 = 30% · 50% · 20%), register 도 formal · neutral · casual 이 섞이게.
7. 결과 파일 말고는 건드리지 않는다. 틀린 곳은 Claude 가 검토표로 돌려보낸다(운영자 검수 전에 Claude 가 먼저 표본 60개를 읽는다).

## 하는 법
1. `git pull` → 브랜치 `ag/business-vocab-N`.
2. 이번 묶음의 단원 · 상황에 맞춰 낱말을 뽑아 `vocab/data/business.json` 에 이어 붙인다(id 는 이어서).
3. `node tools/check-business-vocab.mjs` 가 「N개 · 오류 0」으로 끝나면 커밋 · 푸시. 오류가 있으면 고친다.
