# 안티 그래비티 작업 지시 — 「이야기 만들기」 접속사 카드 · 이야기 늘리기

> 이 파일과 `AGENTS.md` 를 같이 붙여 넣는다. 첫 줄: 「AGENTS.md 를 먼저 읽고, 이 지시문대로만 해. 이번 묶음은 **<초급 | 중급>** 이야기 **N편**이야.」
> 브랜치: `ag/weave-N` (main 에서 새로). 운영자 2026-10-18 「긴 글 만드는 연습 · 접속사로 이야기를 설명하는 연습 섹션」. 화면은 이미 만들어져 있다(배우기 → 이야기 만들기). 이번 일은 **자료**(`docs/weave.json`)를 늘리는 것.
> 지금은 접속사 카드 16개 · 이야기 6편(초급 3 · 중급 3)이 있다 — `docs/weave.json` 을 열어 모양을 먼저 본다.

## 화면이 하는 일 (이걸 알아야 자료를 맞게 쓴다)
이야기 한 편 = 문장 4~6개. 학생이 ① 흩어진 문장을 **순서대로** 놓고, ② 문장 사이마다 **알맞은 접속사**를 4개 중에 고르고(이유가 바로 보인다), ③ **내 이야기를 직접 쓴다**. 끝에 모범 이야기(문장 사이에 정답 접속사를 끼운 글)가 나온다.

## 무엇을
### A. 이야기 더하기 (우선)
`docs/weave.json` 의 `stories` 에 **이야기를 더한다**(이미 있는 것은 건드리지 않는다). 한 묶음 = 초급 10편 또는 중급 10편. 모양:
```json
{ "id": "w-picnic", "tier": "beginner",
  "title": { "ko": "소풍", "en": "A picnic" },
  "sentences": [ { "ko": "…", "en": "…" }, … 4~6개 ],
  "gaps": [ { "ans": "geuraeseo", "opts": ["geuraeseo","hajiman","waenyahamyeon","geureonde"], "role": "result",
              "why": { "ko": "…이라서 「그래서」예요.", "en": "…" } }, … 문장 수 - 1 개 ],
  "write": { "prompt": { "ko": "…", "en": "…" }, "cues": ["…","…","…"], "minSentences": 3, "minConnectors": 2 } }
```
- `ans` · `opts` 는 `connectors` 의 **id**(`geuraeseo` 같은 영문 id). 보기는 정답 포함 **서로 다른 4개**.
- 문장 하나가 접속사로 시작하면 안 된다(접속사는 gap 에서 고른다). `sentences` 에 문장 앞 접속사를 쓰지 않는다.
- 초급 = 한 문장이 짧고(어절 5개 안쪽) TOPIK Ⅰ 낱말 · 해요체 / 중급 = 한 문장이 조금 길어도 되고(어절 9개 안쪽) 이유 · 대조 · 결론이 있는 이야기, 해요체 또는 합쇼체 한 가지로 통일.
- 주제는 일상 · 학교 · 직장 · 여행 · 음식 · 건강 · 취미 · 도시 · 계획 · 후회 · 비교 같은 **여러 가지**로 고르고, 같은 틀(「그래서 → 그리고 → 하지만」)만 반복하지 않는다. 접속사 종류를 두루 쓴다(그래서 · 그러니까 · 하지만 · 그런데 · 그래도 · 그러면 · 왜냐하면 · 게다가 · 또 · 예를 들어 · 결국 · 먼저/그다음에/마지막으로 · 따라서).

### B. 접속사 카드 더하기 (이야기 2묶음 뒤에)
`connectors` 에 카드를 더한다. 후보: 그러나 · 그렇지만 · 그러므로 · 또한 · 그뿐만 아니라 · 반면에 · 즉 · 다시 말해 · 물론 · 사실은 · 그러다가 · 그때 · 갑자기 · 한편 · 이처럼 등(말하는 말과 글말을 나눠 `lv` 에 반영). 모양은 기존 카드와 같다(`id · ko · role · lv · en · use · ex(2개) · tip`). `role` 은 `roles` 에 있는 것만(새 역할이 필요하면 `roles` 에 한 줄 더한다).

## 꼭 지킬 것 (검사 `node tools/check-weave.mjs` 가 막는 것 + 사람이 보는 것)
1. **gap 마다 정답은 하나뿐** — 오답 보기 셋은 그 자리에서 **뜻이 분명히 안 맞아야** 한다. 정답과 **같은 역할**의 접속사를 보기에 두지 않는다(검사). 「그리고」처럼 아무 자리에나 들어갈 수 있는 접속사는 정답이 「그리고」일 때만 보기에 둔다 — 그 밖의 자리에 넣으면 정답이 둘이 된다. 차례(먼저 · 그다음에 · 마지막으로)는 자리로 가른다.
2. `why` 는 한국어 · 영어 모두, 「앞이 ○○이고 뒤가 ○○이라서 「△△」예요」처럼 **왜 그 접속사인지** 한두 문장.
3. 접속사 뒤 문장의 **끝맺음이 접속사와 맞아야** 한다(「왜냐하면 …」 앞 문장은 「-기 때문이에요」로 끝, 「그러니까 …」 뒤는 권유 · 부탁 · 판단). 띄어쓰기 · 맞춤법을 정확히.
4. 영어는 자연스러운 한 문장. 줄임말 따옴표(don't · it's)를 빼먹지 않는다.
5. **기출 아님** — 전부 창작. 실제 사건 · 기관 · 사람 이름은 쓰지 않는다(민수 · 지수 같은 흔한 이름은 괜찮다).
6. 쓰기 칸: `cues` 2~4개(주제어), `minSentences` 3~6, `minConnectors` 2 이상 · 그 이야기의 접속사 자리 수 이하. `prompt` 는 「~를 접속사를 넣어 ~문장으로 써 보세요」 꼴.

## 올리기
- `node tools/check-weave.mjs` 통과 → `node tools/build-weave.mjs`(화면용 `weave.js` 를 다시 만든다).
- 커밋: `docs/weave.json` · `weave.js`. 메시지: `이야기 만들기 N묶음 — <초급|중급> X편` (카드는 `접속사 카드 N개`). 푸시까지 해야 끝(PR 은 만들지 않는다). Claude 가 검토해 넣는다.

# ★ 이번 묶음(1묶음) — 「이음 사다리」 초급 이야기 10편 (2026-10-18 운영자 「설명 · 소개가 어렵고 말이 끊긴다 — 혁신적인 방법」)

> 위의 「무엇을 · 꼭 지킬 것」은 그대로 지킨다. 이번 묶음은 거기에 **새 칸**(`kind` · `key` · `step` · `links`)이 더해진 이야기를 쓴다.
> 왜 · 어떻게 쓰이는지는 `docs/plans/weave-fluency.md`(읽어 둘 것). 먼저 `docs/weave.json` 맨 끝의 시범 `w-intro-me` 를 열어 **모양과 질을 맞춘다**.
> 브랜치 `ag/weave-1`. 커밋 메시지 `이야기 만들기 1묶음 — 초급 이음 사다리 10편`.

## 왜 이런 이야기인가 (이걸 알면 더 좋은 글이 나온다)
학생들은 **소개 · 설명**을 어려워하고 **길게 말하면 자꾸 끊긴다**. 이유는 셋: ① 문장 **가운데서** 막힌다 ② 다음에 무엇을 말할지 모른다 ③ 「-아요.」로 문장을 계속 닫는다.
그래서 이야기 한 편이 **말할 거리의 틀**(누구 → 어디 → 무엇 → 좋아하는 것 → 이유)을 따르고, 문장을 **-고 · -아서 · -는데 · -(으)니까 로 이어 붙이는 연습**(`links`)과, 글이 점점 사라지는 되풀이 말하기에 쓰인다. 그러니 이야기는 **소리 내어 말하기 좋은 글**이어야 한다 — 짧고, 자연스럽고, 입에 붙는 말.

## 쓸 것 — 초급 10편 (주제 고정, 순서 그대로)
| # | id | kind | 제목 | 틀(step 순서) |
|---|---|---|---|---|
| 1 | `w-intro-family` | intro | 우리 가족 | who → where/do → like → why |
| 2 | `w-intro-friend` | intro | 내 친구 | who → do → like → why |
| 3 | `w-intro-town` | intro | 우리 동네(또는 고향) | where → do → like → why |
| 4 | `w-intro-hobby` | intro | 내 취미 | who → do → like → why → wish |
| 5 | `w-explain-why-korean` | explain | 한국어를 공부하는 이유 | point → reason → reason → example → recap |
| 6 | `w-explain-ramen` | explain | 라면 끓이는 법 | point → how → how → how → result |
| 7 | `w-explain-way` | explain | 우리 집에 오는 길 | point → how → how → how → result |
| 8 | `w-explain-food` | explain | 내가 좋아하는 음식 | point → reason → example → recap |
| 9 | `w-tell-yesterday` | tell | 어제 있었던 일 | when → do → do → feel → end |
| 10 | `w-tell-trip` | tell | 지난 여행 | when → who → do → feel → end |
- 이야기마다 문장은 **5~6개**(검사 한도 4~6). 소개 · 설명은 사실(정보) 이야기라 거짓을 지어내도 되지만 **실제 사람 · 기관 · 장소 정보 같은 사실로 오해될 것은 쓰지 않는다**(이름은 민수 · 지수 같은 흔한 것).
- 시범 `w-intro-me` 와 **같은 소재 · 같은 문장을 쓰지 않는다**(「저는 민수예요」 시작은 한 편만).

## 새 칸의 모양 (시범과 똑같이)
```json
{ "id":"w-explain-ramen", "tier":"beginner", "kind":"explain",
  "title":{"ko":"라면 끓이는 법","en":"How to cook ramen"},
  "sentences":[
    {"ko":"라면은 쉽게 끓일 수 있어요.","en":"Ramen is easy to cook.","key":["라면","쉽게"],"step":"point"}, … ],
  "gaps":[ … 문장 수 - 1 개 (위 「무엇을」와 같다) ],
  "links":[ {"from":0,"hint":{"ko":"…","en":"…"},"ans":"…","opts":["…","…","…","…"],"why":{"ko":"…","en":"…"}}, … 2~3개 ],
  "write":{ … 위와 같다 } }
```
- **`key`**: 그 문장의 핵심 낱말 **1~3개**(「기본형」이 아니라 **문장에 있는 그대로**의 글자: 「살아요」 O · 「살다」 X). 글이 사라지는 연습에서 학생에게 남는 단서가 된다 — **그것만 보고도 문장을 떠올릴 수 있는 말**을 고른다(명사 · 동사 · 부사 위주, 조사 X).
- **`step`**: 틀의 칸 — intro `who · where · do · like · why · wish` / explain `point · reason · example · how · result · recap` / tell `when · who · do · feel · end`. **첫 문장은 intro `who` · explain `point` · tell `when`**. 같은 step 이 두 번 나와도 된다(위 표의 틀을 따른다).
- **`links`**(이어 한 문장으로): 이웃한 두 문장(`from` 번째 + 그다음)을 **한 문장으로 이은 정답**(`ans`)과 틀린 보기 셋(`opts`, 정답 포함 4개 · 서로 다름).
  - `from` 은 0부터(0 = 1·2번째 문장). 한 이야기에서 `from` 이 겹치지 않는다. **2~3개**, 서로 다른 연결(-고 · -아서/어서 · -는데 · -(으)니까 · -지만 · -(으)면 가운데에서 골고루).
  - **정답은 두 문장의 말을 그대로 이어 붙인 것**이다 — 새로 고쳐 쓰지 않는다(두 문장의 `key` 첫 낱말이 정답에 다 들어 있어야 한다. 검사가 본다). 높임 · 시제는 원문대로 둔다.
  - **오답 보기 셋은 같은 두 문장을 다른 연결어미로 이은 것**이다(예: 「-고」 · 「-아서」 · 「-지만」 · 「-(으)면」). 그리고 **`hint` 의 뜻으로 읽을 때 정답 하나만 맞아야 한다**(힌트 「이유 → 결과」이면 「-아서」만 맞고 「-고」 「-지만」 「-(으)면」은 뜻이 안 맞다). 같은 뜻의 연결어미 둘(예: 「-는데」와 「-지만」 둘 다 반대)을 보기에 함께 두지 않는다.
  - 보기 모두 **문법적으로 맞는 문장**이어야 한다(「-아서」 보기가 「와서」 대신 「오아서」처럼 어색하면 안 된다) — **틀린 이유는 뜻이 안 맞는 것**이지 활용 오류가 아니다. 보기는 마침표가 맨 끝에 하나뿐인 한 문장.
  - `hint`: 「이유 → 결과로 한 문장으로」 · 「나란히 더해 한 문장으로」 · 「기대와 다른 것을 한 문장으로」처럼 **어떻게 이을지** 한 줄(ko · en). `why`: 왜 그 연결어미인지 한두 문장(ko · en).

## 이번 묶음에서 특히 지킬 것
1. **입에 붙는 말** — 소리 내어 말해 보고 걸리면 고친다. 문장은 짧게(어절 5개 안쪽, 소개 · 이야기는 6개까지), 해요체 한 가지로 통일(「-ㅂ니다」와 섞지 않는다).
2. **gap 과 links 가 겹치지 않게** — 한 쌍의 이웃 문장에 gap(접속부사)과 links(연결어미)가 둘 다 있는 것은 괜찮지만, **gap 정답이 「그런데」인 자리의 link 는 「-는데」**, 「그래서」인 자리는 「-아서」 같이 **뜻이 같아야** 학생이 헷갈리지 않는다(다른 뜻으로 잇지 않는다).
3. **한 이야기 안에서 접속사 · 연결어미를 골고루**(`gaps` 의 정답이 모두 같으면 안 된다).
4. 설명 이야기의 **how 칸은 순서가 분명한 차례**(먼저 · 그다음에 · 마지막으로의 gap 에 쓰인다). 라면 · 길 이야기는 **실제로 따라 할 수 있게** 쓴다(물 끓이기 → 면 넣기 → 스프 넣기, 지하철 · 버스 말고 「걸어서 · 쭉 가서 · 왼쪽」 같은 길 말).
5. 영어(`en`)는 자연스러운 영어 한 문장 — 「It is because …」 같은 직역투를 피한다.
6. **`write.cues` 는 틀의 칸을 따른다**(소개: 이름 · 사는 곳 · 하는 일 · 좋아하는 것 등), `minSentences` 4~6 · `minConnectors` 2 이상.
7. 기출 아님 · 실제 사건 · 단체 · 이름 X (위와 같음).
