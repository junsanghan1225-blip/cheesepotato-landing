# 안티 그래비티 작업 지시 — 조사 워크북 「조사 블록」 구역 (맥락 카드 · 블록 분해 · 고르기 · 블록 채우기)

> 이 파일과 `AGENTS.md` 를 같이 붙여 넣는다. 첫 줄: 「AGENTS.md 를 먼저 읽고, 이 지시문대로만 해. 이번 묶음은 **<단원 id · 예: pt-26-1~pt-26-5>** 이야.」
> 운영자 2026-11-04 「조사마다 블록처럼 · 문장에 들어간 조사마다 보여주기 · 연습이 다 똑같다 · 문제 느낌으로」. 시안: `에브리코리안즈_목업_조사워크북_N이가_섹션시안_v0.2`(15~16쪽). **이 모양은 다음 조사 워크북에도 쓴다.**

## 무엇을
한 단원(조사 하나)마다 **네 가지 자료**를 만든다. 책 틀(Claude)이 이걸 쪽에 얹는다.
1. **맥락 카드 4~5장** — 「언제 이 조사를 쓰나」를 카드 한 장씩. 기존 표(`Context · When · Example · English`)를 대신한다.
2. **블록 분해 4문장** — 한 문장을 낱말 · 조사 · 서술어 블록으로 쪼개고 블록마다 역할을 단다.
3. **고르기 4문제** — 번호 · 빈칸 · 영어 뜻 · 보기 ①②(③). 시험 문제 모양.
4. **블록 채우기 3문제** — 블록으로 쪼갠 문장에서 조사 블록 하나를 비워 둔다. 보기는 단원 전체에서 공통으로 4개.

- 결과 파일: **`docs/books/particles-workbook.blocks.json`** 한 파일(묶음마다 이어서 더한다). 브랜치 `ag/particles-blocks-N`. 키 = 단원 id.
- 단원 목록은 `docs/books/particles-workbook.json` 의 `parts[].units` 순서. `pt-guide` · `mt-*`(모아 보기)는 만들지 않는다. `ct-*` · `rv-*` 는 이번에 만들지 않는다(조사 하나씩인 `pt-26-*` 만).

## 모양
```json
"pt-26-1": {
  "cards": [
    { "tag": {"ko": "새로 꺼내는 것", "en": "new information"},
      "when": "처음 이야기에 올리는 사람 · 물건",
      "ko": "저기 고양이{가} 있어요.",
      "en": "There is a cat over there." }
  ],
  "split": [
    { "en": "There is a cat over there.",
      "blocks": [
        {"t": "저기",   "role": "장소"},
        {"t": "고양이", "role": "주어 말"},
        {"p": "가",     "role": "주어 조사"},
        {"t": "있어요", "role": "서술어"} ],
      "note": "" }
  ],
  "choose": [
    { "q": "저기 고양이___ 있어요.", "en": "There is a cat over there.",
      "opts": ["이", "가"], "answer": 1, "why": "고양이 ends in a vowel, so 가." }
  ],
  "fill": [
    { "blocks": [ {"t": "하늘", "role": "주어 말"}, {"p": "가", "role": "조사", "blank": true}, {"t": "파래요", "role": "서술어"} ],
      "en": "The sky is blue." }
  ],
  "pool": ["이", "가", "는", "을"]
}
```
- `cards.ko` 에서 **그 단원의 조사 글자만 `{ }` 로 감싼다**(책이 주황 밑줄로 바꾼다). 카드 문장에 같은 조사가 둘이면 둘 다 감싼다.
- `blocks` 는 **띄어 쓰는 단위로** 쪼갠다. 낱말 블록은 `t`, 조사 블록은 `p`. 낱말(`t`) 바로 뒤에 조사(`p`)가 오면 **붙여 쓴 것으로 합친다**(예: 고양이 + 가 → 고양이가). 합치면 원래 문장이 정확히 나와야 한다 — 검사가 이걸 본다.
- `blank: true` 인 `p` 의 글자(`가`)가 **정답**이다.
- `choose.answer` 는 `opts` 안의 번호(1부터). `why` 는 영어 한 줄.

## 역할 이름은 이 목록에서만 (표를 반듯하게 하려고)
`주어 말` · `주제 말` · `목적어 말` · `장소` · `때` · `사람` · `도구` · `이유` · `수 · 양` · `서술어` · `부사` · `감탄` · `이어 주는 말` · `나` · `말` · 그리고 조사 블록은 `주어 조사` · `주제 조사` · `목적 조사` · `장소 조사` · `방향 조사` · `함께 조사` · `도구 조사` · `비교 조사` · `조사`. 목록에 없는 역할이 꼭 필요하면 만들지 말고 `docs/antigravity/particles-blocks-notes.md` 에 단원 id 와 한 줄로 적는다.

## 만들 개수와 모양 (단원마다)
| 자료 | 개수 | 규칙 |
|---|---|---|
| `cards` | 4~5 | 그 조사의 **서로 다른 쓰임**마다 한 장(새 정보 · 방금 본 것 · 질문의 답 · 이유 절 · 아니다/되다 앞 …). 쓰임이 4개 안 되면 4장까지만. `tag` 는 한국어 · 영어, `when` 은 한국어 한 줄. |
| `split` | 4 | 카드와 **다른 문장**. 한 문장에 조사가 둘 이상 들어간 문장을 1개 이상(예: 저는 의사가 아니에요 → 는, 가). 블록은 문장당 3~7개. |
| `choose` | 4 | ① 받침 있고 없음으로 이/가 고르기 ② 질문의 답 ③ 두 조사가 헷갈리는 문장(보기 ③까지) ④ 두 빈칸에 한꺼번에 고르기(보기를 짝으로: `이 · 이`, `가 · 은` …). 한 문제 정답은 **하나**여야 한다. |
| `fill` | 3 | 블록 3~4개 문장. 비울 블록은 **이 단원의 조사**. |
| `pool` | 4 | 이 단원 조사 + 헷갈리는 조사 3개. 순서는 섞지 말고 단원 조사가 첫째. |

## 규칙 (꼭 지킬 것)
1. **한국어가 자연스럽고 정답이 하나**여야 한다. 의심스러우면 그 문제를 빼고 `docs/antigravity/particles-blocks-notes.md` 에 단원 id 와 한 줄로 적는다.
2. **그 단원까지 배운 조사 · A1~A2 낱말 안에서만.** 단원 순서는 `parts[].units`. 아직 안 배운 조사를 문장에 넣지 않는다(예: 이/가 단원에 에서 · 으로 금지. 이미 배운 은/는 · 이다 · 을/를 정도는 가능).
3. 문장은 전부 새로 만든다. **실제 TOPIK · EPS 기출 문장 금지.** 사람 이름은 민수 · 지영 · 수진 같은 흔한 이름만, 기관 · 전화번호 · 실제 장소 이름 금지.
4. 영어 뜻은 자연스러운 한 문장. 줄표(—) 금지(쉼표 · 쌍점으로). 한국어 설명 문장에도 광고체 금지.
5. 같은 단원 안에서 **문장이 겹치지 않게**(카드 · split · choose · fill 모두 합쳐 서로 다른 문장). 같은 낱말을 5번 넘게 쓰지 않는다.
6. 다른 파일 · 다른 단원 · 이미 있는 키를 고치지 않는다. 시범 키는 Claude 가 `pt-26-1` 을 먼저 넣어 둔다.

## 하는 법
1. `git pull` 로 main 을 받고 브랜치 `ag/particles-blocks-N` 을 만든다.
2. 단원 8~10개씩 만든다. 각 단원 id 의 조사(`pt-26-N` 의 제목 · 쓰임)는 `node tools/think-list.mjs particles-workbook --todo pt-26-1` 로 본다(「Watch out」 · 표 앞 3줄이 나온다).
3. `docs/books/particles-workbook.blocks.json` 에 키를 더한다(JSON 문법이 틀리지 않게).
4. 스스로 확인: **블록을 합쳐 읽어 문장이 말이 되는지** 한 번 소리 내어 읽는다 · `choose` 의 `answer` 가 정말 하나뿐인지 본다 · `fill` 의 정답이 단원 조사와 같은지 본다.
